# 会话核心、问答与辅助对话 {#overview}

## 一次发送经过谁 {#ownership}

打开项目后，窗口级 Host 路由到该工作区适配器；每个会话首次发送时才创建独立 OMP 进程，工作目录为项目根。目录进程使用 `--no-session`，用于模型、命令、角色和会话目录查询，不执行另一份会话。五个会话允许对应五个会话进程加一个目录进程，切换或刷新 Renderer 不等于关闭它们。

```text
窗口 Host → 工作区 omp-agent
  ├─ 目录 OMP：目录、补全、角色、历史管理
  └─ 会话 OMP：模型、工具、输入队列、问答与运行记录
             ↓ 同一会话投影
       主对话 / 子代理详情 / Agent 交互观察
```

OMP 是运行与持久记录所有者，适配层生成 UI 投影，Host 只路由。桌面连续链路直接接收帧；Web 恢复链路按水位续传，超出保留范围取完整快照。打开历史不能重发工具或模型任务。关闭会话释放进程并保留已保存历史；删除则先停止对应进程，经核心确认永久删除后再移除索引。

目录和会话各自协商协议。旧核永久缺能力与当前进程暂不可用是不同问题：前者明确不支持，后者是启动/退避故障。目录 ready 后收尾期间退出，不得被缓存为可用；命令目录更新后，旧查询返回的已移除命令也不能重新执行。

## 命令与模型入口 {#commands}

输入 `/` 取得目标 OMP 的真实目录与说明；动态补全按 UTF-16 光标和替换区间工作。未知命令、仅 TUI 可执行项或带附件斜杠输入均拒绝，不会兜底送给模型。命令更新应使旧候选失效。

临时会话模型和用户角色持久配置分开：工具栏决定下一次输入，设置中的角色决定长期配置。临时改选不写角色文件，也不改变其他会话。模型连通性测试已无独立 RPC；MCP 也不能从空状态快照推断实际连接。

可选 `OMP_SKILLS_DIR` 与 `OMP_WIKI_DIR` 由 Host 环境传入同一工作区的目录/会话进程，不依赖 offline。前者由 OMP 决定技能优先级；后者是 **可写** 知识目录覆盖，导入/删除都会作用于该目录。远端只解释远端环境，不将本机目录注入远端，不承诺共享 SQLite 的跨机器并发安全。

## 回答问题和工具审批 {#questions}

- 富 ask 可一次包含多题、多选、选项说明、预览与推荐项。按题选择或用「其他」补充，确认时按题 ID 回传。相同文字的两题也是独立问题。
- 取消是取消整次请求；倒计时到期可按核心推荐策略收口。旧核可能逐题退化为选项与多行输入，不代表同时具备富问答。
- 普通 select/confirm/input/editor 使用现有询问界面。敏感输入必须用密码输入，不进入持久草稿；多行编辑保留 prefill 与首尾空白。
- 工具审批只有 OMP 策略启用时出现，选项为 `Approve` / `Deny`，提示说明工具与目标。默认 yolo 不确认；没有旧六档权限卡，会话级或永久允许由 OMP 配置管理。
- 审批超时、连接断开或界面销毁按拒绝处理。不要把没有可点按钮的遮罩当作正常等待，也不要把 RPC success 当作实际批准。

无宿主展示面的扩展通知、状态组件或打开 URL 请求应取消回执，不让核心一直等待。可见普通扩展文本只投影一次并支持历史；隐藏文本不显示。TUI 自定义 renderer、图片与布局不在承诺内，技能正文另按[技能规则](./skills)隐藏。

## 辅助对话 BTW {#btw}

从「辅助对话」、划词提问或 `/side`、`/btw` 打开独立 pane。裸别名只开空 pane，**不调用模型**；带问题首问和后续追问由父会话原生 BTW 执行，不创建普通子会话冒充。

BTW 继承父会话当前模型与上下文，包括正在 streaming 的上下文；它不用工具，不增长主 transcript，不提供独立模型、思考或计划切换，也不支持附件/结构化上下文。不能把 BTW 当可修改项目的第二代理。旧核未知 BTW 会明确报能力缺失，草稿不应静默送到主对话。

首问受理后绑定真实主题地址，随后才是增量和终态；受理不等于回答完成。停止只取消当前匹配主题，不 abort 主回合。关 pane 只是卸载视图，不删除主题或停止父会话；历史入口可重开已保存主题，重启后继续追问。保存失败必须可见，部分回答和 complete/error/cancelled/interrupted 真实状态应保留。旧普通副屏记录不自动转成 BTW 历史。

## 阅读执行详情与控制 {#subagents}

主/子执行页保留任务输入、每次工具及结果、后续唤醒和回复。子代理详情按真实 ID 与父会话归属读取原生记录，不按到达顺序猜配对；实时通知只是触发补读，不重复写执行记录。

顶部发送/停止只有父 owner 能证明可控制时才可用。已结束或纯冷历史只读，缺少终态证据显示未知。普通助手单条 stop 不是整任务结束；主回合依据 `agent_end`，子任务依据结构化交付与生命周期判断。IRC 协调包装和后台提示在执行页不铺开，真实通信去[Agent 交互页](./agent-interactions)核对；虚拟 `agent://` 写入不算磁盘 diff。展开或向上阅读后不应被重复补读拉走位置。

## 诊断与验收边界 {#acceptance}

故障时先保留事件名、会话/请求关联、阶段、PID 与耗时，不保存原始协议帧、正文、答案、附件或凭据。适配器日志经 stderr→Host→Main 文件链路，协议 stdout 不能混入日志。`advisor_cost_changed` 与 `session_settled` 是合法辅助帧，不等于用户轮终态；未知/畸形帧仍应诊断。

核心验收需要逐项观察真实入口：普通消息、技能与补全、命令与补全、子代理过程、模型临时/持久双入口，以及并行问答、冷改名/删除、停止和历史。类型检查、fake 协议或页面可打开不能替代 GUI。历史 Windows 结果与尚未完整验收的 Web replayable、全部 BTW 和 CentOS 场景分别保留，不由本站升级为通过。

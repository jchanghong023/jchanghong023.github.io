# 产品范围与上游差异 {#overview}

## OmpCode 是什么 {#identity}

OmpCode 是持续跟进 ZCode 界面的个人 Fork，核心替换成 [OMP](/omp/)。对用户统一显示 OmpCode 品牌与 OMP 图标，保留上游的布局与常用交互，而不是把 OMP 原始协议交给使用者。第一阶段重点是既有会话、子代理卡片/详情和 Todo 面板；只有这些界面不能表达 OMP 能力时，才考虑专用界面。后续阶段是方向，不是已经完成的功能清单。

源需求记录的已合入上游基线为 ZCode `v3.14.3`、提交 `29628c9acdb81b703bbd4080c207a0e7ce5e276e`；这不表示上游当前最新版本。产品只维护 `main`，支持 Windows 与 CentOS 7，不支持 macOS 和通用 Linux RPM。两平台界面相同；CentOS 发布标记只允许改变渲染性能策略，离线环境门控只改变后端可用性。

## 核心、数据和更新隔离 {#isolation}

OMP 拥有模型循环、工具执行、凭据和会话。OmpCode 适配器为每个会话惰性拉起一个 `omp --mode rpc-ui` 子进程，另以目录进程查询工作区能力。它们走 stdio，不给内嵌 OMP 开监听端口，不复用或终止用户已运行的 OMP。保留的上游 CLI 源码快照不是回退运行时。

安装包内嵌本人 OMP Fork 的 Release 资产，准备资源时必须校验发布 SHA256，包括缓存复用。它不安装、覆盖用户已有 OMP，但使用相同配置来源；因此改动 OMP 角色或凭据也可能影响日常 OMP。具体根目录和 Profile 见[模型与数据](./models-and-commands)。

应用默认业务根为 `~/.ompcode`，项目配置为 `.ompcode/`，不读取、迁移或写入上游 `.zcode` 数据。有效 `OMP_CONFIG_ROOT` 会派生独立 `_ompcode` 应用根。Explorer 菜单和更新缓存按产品隔离；不过内部 `zcode://` scheme、appId 等仍与上游共享，双装时深链可能由最后注册方接管，任务栏可能同组。**安装身份冲突不代表共享业务数据。**

正式包从本 Fork Release 手动更新，不从 ZCode 自动更新 feed 获取版本，也不受上游强更线阻止启动。开发端口区分于上游：桌面调试 9230、桌面开发 5194、Web 5193、server 默认 3033；运行期自建服务使用临时端口。桌面连续交付与 Web 按水位恢复是两种链路，不能互相替代。

## 已取消，不寻找替代入口 {#cancelled}

- **手机远控**：二维码、中继、证书创建和专用 API 均取消，两平台一致，不保留禁用入口，也不恢复官方云远控。已有外部证书/数据不会由此主动删除。通用 Web、SSH/WSL/Docker/Server 工作区与 Host attachment 边界仍保留，不代表支持在这些系统运行桌面安装包。
- **会话分享/导入**：按钮、公开分享页、上传下载、深链导入均取消。不应通过旧链接触发导入或网络操作。普通复制、附件、历史和 Web 登录不是分享，仍保留。外部已发布记录不因本地代码删除而撤销，本地旧导入目录也不批量删除。登录 provider 已注册的 callback 路径可能保留旧名称，不代表分享恢复；旧分享返回参数应被忽略，登录返回 Web 根页。
- **旧账号/套餐**：启动登录门禁与套餐配额 UI 废弃，使用 OMP 模型配置。

## 不等价能力与实际替代方式 {#limitations}

| 不可用或受限能力                              | 使用时应如何理解                                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 插件/技能市场、插件安装                       | 市场入口隐藏；[技能](./skills)是目标 OMP 可执行目录，不是安装商店                            |
| 已保存工作流 GUI、动态 workflowRun            | 无等价引擎，不提供假空结果；原生 OMP 编排命令是另一套能力                                    |
| fork 某轮、重试、编辑已发送消息、文件回滚     | 当前均不可用；辅助 BTW 不属于分支/编辑，不承诺未来开放                                       |
| 旧 build/edit/plan/yolo 协作模式和旧 goal API | 不恢复旧状态机；改用[原生 `/plan`、`/goal`、`/loop`](./omp-native-commands)                  |
| 队列编辑、重排、删除、立即发送                | 不支持；保留 guide→steer 与 queue→follow_up，每轮一条                                        |
| 历史聚合用量                                  | 应用级空快照是能力边界；会话级累计值可用，不等于全应用历史统计                               |
| 独立模型连通性测试、提交说明生成              | 无对应核心接口；模型是否可用以实际会话为准                                                   |
| MCP/扩展运行连接状态                          | 配置存在不代表连接；未提供的运行状态明确说明                                                 |
| 审批六档卡、持久权限按钮                      | 原生 Approve/Deny 询问；默认 yolo 无弹窗，持久策略归 OMP                                     |
| Off-Peak、旧后台任务、回复赞踩                | 错峰不可用，旧后台任务不启动；无法持久化的赞踩隐藏                                           |
| legacy session 实时事件                       | 为空；桌面/Web 主链路走 v4，不据此判断没有输出                                               |
| storage prepare worker                        | 仅协议 ready 握手，不表示存在旧 CLI SQLite 历史库                                            |
| 附件与冷历史                                  | 见[类型限制](./integrations#attachments)及[恢复规则](./session-recovery)，不能按上游功能推断 |

## 发布与证据边界 {#evidence}

Windows EXE 与 CentOS ZIP 由独立的零自定义输入手动 workflow 从 `main` 发布，Tag 含 UTC 日期、时间、run ID 与 attempt；发布不单独跑测试。发布成功只证明那次资产发布，不能代替功能验收。测试门也不会自动触发发布。

源文档保留手机远控删除、分享删除、OAuth 跳转等不同历史证据：分享取消的完整 GUI 验收仍有未执行范围，OAuth 隔离回归不是连接真实 provider 的证明，CentOS 目标环境和当前发布包也不能从 Windows 旧结果推断。维护时依据[源需求](https://github.com/jchanghong023/OmpCode/blob/main/docs/requirements/FORK.md)，不要把同名上游功能认作已适配。

# 输入区、上下文与草稿 {#overview}

## 发送前看原工具栏 {#toolbar}

电脑输入框沿用单行工具栏：左侧附件，右侧模型、思考档与发送，Git 和上下文等只读状态就地呈现，不另增第二行。窄窗口优先保留原操作及分支名；手机布局不增加这些入口，不代表专用手机远控仍存在。

- **模型/思考**：工具栏代表下一次提交意图，不是永久角色配置。新任务与手动换模型默认取支持的最高思考档（含核心支持的 off）；已有会话从自身事实初始化，手动改选后保留。首发/续发提交时应用到对应会话，不写 OMP 配置。
- **计划**：没有计划模型/计划模式按钮，直接输入 `/plan` 使用 OMP。设置里的 plan role 仍有效；旧草稿的按钮恢复标记被忽略，不应重新切回旧模型。
- **压缩**：没有压缩按钮或自动压缩开关。手动输入 `/compact`，自动压缩由 OMP 会话管理；圆环不是压缩控制。
- **Git**：分支与 dirty 数来自 Host 已有 summary，点击进入既有审阅；非 Git 或不可用时隐藏，不代表工作区被删除。

BTW 辅助 pane 固定继承父模型，不适用主输入区这些切换规则，见[辅助对话](./omp-core-integration#btw)。

## 上下文圆环不是套餐余额 {#context}

总量来自同会话 OMP 状态；容量未知不画圆环，刚创建的零 token 会话可以显示 0%。悬浮面板展示 `/context` 取得的系统提示、工具、技能、消息、空闲空间和自动压缩预留等**估算分项**，并给出 token 和容量占比。

分项缺失、格式不识别或容量不一致时，只显示已确认总量，不拼造细项。每次新总量替换清理旧分项，终结轮与成功压缩后重新读取。读取失败保留未知/已知值，不伪造新用量。

```text
先交付冷历史 → 读取同会话 get_state → 空闲时 /context → 更新圆环/估算
用户输入同时到达 → 等本地查询收口再发送；查询失败不阻断输入
```

弹层内部查询不应成为聊天消息。正在活跃执行时不额外发 `/context` 抢占轮次，也不能将前一会话的迟到结果显示给当前会话。

## 草稿何时保存、何时恢复 {#drafts}

普通输入只更新内存最新值并合批保存，不逐字重写全量草稿。发送、切会话、失焦与正常退出会 flush；失败时以最后一次成功持久化为恢复依据，强杀不保证尚未保存内容。

同 renderer、同 workspace identity 和会话 scope 的多个 pane 共用一个草稿 owner，正文、富 JSON、mention 与模型意图一致；恢复不能抢另一编辑器焦点或选区。正文相同但 mention 身份变化也应保存，不能只比较 Markdown 文本。

提交会冻结来源版本：A pane 发送后，B pane 的新正文、富节点或附件不应被 A 旧回包清除；发送失败只恢复尚未被新编辑替换的来源草稿。切到别的会话后失败仍归原会话，不污染当前错误或 pending。

首次会话绑定稳定 UUID，只依据 Host **成功持久化**的迁移事实迁移草稿，不按标题/正文/时间猜测。目标已有新内容或 pending 则整份目标优先，冲突来源备份保留；目标仅初始化配置不应吞掉来源正文，显式手动模型意图可保留。写入失败不删除来源，重复迁移应幂等。

## 问答、发送与停止 {#interactions}

敏感 input/editor 只在密码框中填写，不进入问答草稿 store。多行 editor 的初始值可编辑，确认保留首尾空白；取消结束请求。富 ask 的多题、多选、推荐和自定义按题分别回答，不因文字相同合并。

运行态空草稿显示 Stop，空闲显示 Send；两者的悬浮提示各自生效，切换后不残留旧提示。运行中有追加内容时先理解[引导/排队](./session-recovery#queue)，而不是把发送当重新开始任务。

## 出错与验收边界 {#evidence}

遇到旧模型覆盖、跨 pane 草稿丢失、恢复成重复 UUID、上下文串会话或提示浮层异常，记录来源 scope、操作顺序与脱敏日志；不要靠清空整个配置解决。验收须比较发送内容、切换/重启后内容及富结构，验证失败/迟到结果，并保留真实输入焦点。

源记录包含 Windows GLM、双 pane/Lexical 与 mention 组件、稳定 UUID 和冷恢复的历史证据；原生 IME/失焦、目标网络盘、真实 Web GUI 与完整附件上传不能由这些结果推断。本站没有执行任何产品测试。

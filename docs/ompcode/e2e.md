# 真实桌面专项：怎样证明核心流程可用 {#overview}

这是维护者的跨功能验收说明，不是普通用户必须执行的入门练习，也不是本站已经完成的产品测试。源专项指定 Windows、OpenAI Codex / GPT-6 Luna / High，检验角色持久化、真实三子代理、广播、文件操作、GUI 和冷恢复。全部通过只能说明报告绑定版本在该范围基本可用，不能扩大到全部功能或 CentOS。

## 开始前先确认操作与隔离 {#isolation}

专项涉及 Computer Use/真实 GUI，应另有当次执行授权。优先独立桌面会话；Windows 虚拟桌面不等于独立鼠标键盘。无法安全截图/点击/输入目标实例就记录 BLOCKED，不能直接用 RPC 或测试替代，也不能假定隐藏窗口可操作。

创建唯一临时测试根，OMP 配置、工作区和证据分开。只给测试进程设置绝对 `OMP_CONFIG_ROOT`，应用自动派生兄弟 `<OMP_CONFIG_ROOT>_ompcode`；应用 v2 与 electron、OMP 原会话/子记录分属各自根。逐一核对 OMP_PROFILE、PI_PROFILE、PI_CODING_AGENT_DIR、PI_CONFIG_DIR、认证来源和 OMP_RPC_ARGS_JSON 等覆盖，不是设置一个变量就完成隔离。

独立应用身份、独占空闲端口、明确测试 PID/进程树；确认源码/包版本。不能连接、关闭日常实例或修改全局/用户环境。文件和证据只能落测试范围，解析路径不得通过链接/junction/重解析点越界。

## 认证不是复制数据库就安全 {#credentials}

只读识别实际认证来源，必要凭据安全放进隔离配置。当前 agent.db 不仅含认证，SQLite 先一致快照再只提取目标 provider 必需记录，不复制整库当纯认证文件，也不复制会话/角色/缓存。

OAuth 副本可能共享刷新令牌：无法证明不会影响真实登录，就在模型调用前 BLOCKED；不得到真实根执行会自动刷新回写的检查，不关闭刷新/认证来绕过。日志、截图、报告和 Git 均不可包含认证材料，结束采集后无论成败都清理认证副本。

## 保存角色并重启读回 {#models}

1. 在隔离 GUI 设置确认运行 Profile；如换 Profile，保存并完全重启后才编辑角色。
2. 将 default 和 task 角色均选为真实目录中的 `openai-codex/gpt-6-luna`、`high`，等待分别自动保存，重开读回。
3. 只读核对实际 role 配置及其他字段/注释保留；再退出并用同根重启，仍显示同样角色。
4. 新建会话后通过工具栏将**本轮**模型/思考调整到同样值，不能以角色设置代替会话临时值。草稿默认最高档可能高于 high。
5. 后续核对主代理及三个通用 task 实际运行模型/思考，不能靠源码目录存在推断账号权限。

目标模型缺失、不支持 High 或认证不可用就 BLOCKED，不换模型/降档。角色持久格式可表示为 `openai-codex/gpt-6-luna:high`，以目标 OMP 实际目录解析为准。

## 三个文件、三项独立执行 {#task}

在临时工作区顶层预置无扩展名 a1/a2/a3，内容分别 old-a1/old-a2/old-a3，UTF-8 无 BOM、无末尾换行。计数只算顶层普通文件，不递归，不把配置/证据文件混入。

隔离配置须在新主会话前启用 `task.structured: true` 并重启，保证通用 task 有真实 yield 提交，三个代理继承 @task，共享同一测试工作区；不能换成另一代理类型、另一 worktree 或伪造结果。普通 bash 是 POSIX，顶层计数使用 eval 的跨平台文件 API，避免混用 Windows find/cmd 语法。越界命令即使最终文件正确也保留 FAIL。

通过真实 GUI 输入**源规程的完整任务提示词**，不直接 RPC 注入；提示词的可操作要点是：一次批量分配 Agent1/2/3 各管一个同名文件，各自实际计数；主代理以真实 ID 广播一次，各子真实回复文件名/数量；收齐后各自检查存在、明确删除旧文件、创建新文件、读回、用 yield 提交最终结果；最后主代理自然语言汇总。完整逐字文本请取[源规程第七节](https://github.com/jchanghong023/OmpCode/blob/main/docs/requirements/e2e.md)，本站不另维护提示词副本。

广播是写 `agent://all` 或真实 `agent://<ID>`，不是磁盘文件；自动消息不是要求没有后台任务的子代理循环 wait。验收真实收件人/回复与归属，不比较精确时序/间隔；并发计数可不同，但对象必须同一工作区。主代理自己写文件不能代替三子执行，普通回复不能代替真实结构化完成。

## 四组结果必须相互对照 {#results}

| 检查面       | 需要的实际证据                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| 主代理 GUI   | 用户任务正确、三个真实身份/状态、广播和回复、完整自然语言总结、结束恢复正常，失败不报成功                   |
| 三个详情     | 名称/任务/目标正确，各自计数、通信、先删后写及读取校验的真实工具参数/结果和终态；切换不串记录               |
| Agent 交互页 | Main+三子层级、派发/广播/回复/结果真实方向，逐条原文可对照、选择与长内容可读，缺时间按未知/记录时间         |
| 实际文件     | a1/a2/a3 最终各为对应两个 ASCII 字节，无 BOM/换行，旧内容消失，路径在临时根，各自由对应代理完成，无其他改动 |

最终文件存在不足以证明子代理正确；父总结也不足以证明广播真实。OMP 没有统一全量通信审计库，实时或冷恢复缺所需记录必须报告缺口，不能补造。各界面截图与原始工具/会话记录交叉核对，不只检查 DOM 有某段文字。

## 同根冷恢复，不能重跑代替 {#recovery}

任务完成后完全退出测试实例，以同环境与同根重开原 UUID：角色仍正确、原主回复、三个原子代理 ID 的执行过程、通信历史与文件都在，不显示虚假运行。恢复只读，不新建替代会话、不重发文件任务。关闭 tab 再打开与完整进程重启都是不同边界，不能用前者代替后者。

## 报告与可行性边界 {#evidence}

每项标 PASS（实际满足）、FAIL（已执行不符）、BLOCKED（工具/环境/认证/证据不足）；有阻塞可继续无依赖检查，依赖项不能算通过，不无限等待或重复发送。全部项满足才可整体 PASS。

报告包括平台、HEAD/差异指纹、应用/OMP/工具版本、隔离结果、实际模型、角色重启读回、三代理计数/通信/文件证据、各 GUI/恢复、失败复现与脱敏截图日志位置，以及是否影响真实配置。不同源码/二进制快照不能拼成一次通过。保留失败必要非敏感证据，只清理本次创建且可确认的目录，不动他人数据/进程。

源文档的可行性审查只确认需求与源码能力，没有完成该指定 GPT-6 Luna 专项；安全 OAuth、可操作 GUI、目标模型与完整持久记录仍是执行前提。其他 GLM 或组件历史结果不自动满足此专项。本站没有请求认证、启动产品或执行文件任务。

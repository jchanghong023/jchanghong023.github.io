# 会话历史、队列与故障恢复 {#overview}

## 关闭、恢复与永久删除 {#history}

OMP 当前配置根/Profile 的会话文件是历史事实源，应用任务索引只是投影。列表标题取 title 或首条用户输入，不是身份；首次会话从临时 ID 绑定文件 UUID 后，任务、订阅、草稿和组织信息应指向同一会话。

- **关闭**只释放当前引擎，保留已落盘历史，稍后可重开。
- **恢复**使用原稳定 ID，先交付冷历史再回读状态，不自动重发原任务。较早历史可继续分页，不能把列表读取窗口当成删除；源验收包含超过 100 会话和 4000 条记录的读取。
- **删除**是永久删除 OMP 文件：先确认文件删除成功，才移除索引/广播。失败应保留可重新打开的历史，不显示「已删除」。操作前确认目标会话和不再需要的记录。
- **换根/Profile**不迁移旧历史，索引隔离；切回后原分组、排序、置顶、归档、未读及定时关联仍应保留。

临时 ID→UUID 的 rekey 成功后，Host 在既有任务元信息持久化权威 from/to，UI 才迁移草稿；重复事件幂等，断线/重启可从任务元信息补迁。无映射不能按同标题或时间猜测归属。扫描失败也不能当「文件不存在」清理任务，非 ENOENT 错误保留上一成功投影。

## 运行中追加：引导还是排队 {#queue}

| 模式         | 实际核心操作 | 用户可见含义                                                         |
| ------------ | ------------ | -------------------------------------------------------------------- |
| guide / 引导 | `steer`      | 在当前 OMP agent 轮工具间补充方向，UI 建立对应新用户轮并关联后续事实 |
| queue / 排队 | `follow_up`  | 等待后续轮，排队时不算正在执行；每轮一条                             |

两个队列由 OMP 持有，Renderer 不保存第二份已接受队列。相同文字的多次输入有独立 command ID，依顺序和真实条数一对一消费，不合并。收到用户 `message_start` 或相应核心对账事实才激活队首；空快照/RPC success 不能证明已消费，停止期间等待的输入可能已取消。

当前不支持编辑、重排、删除或立即发送队列项。停止、失败或进程退出应收口相关轮次/交互，不留虚假「工作中」；迟到 ACK 或完成帧不能重新覆盖终态或关闭新轮。不要为不确定的回执连续重发同一任务。

## 文件变化与子代理历史 {#records}

文件统计以成功工具结果为准。hashline 输入提供实际路径，工具统一 diff 提供增删行，多文件分别归属对应轮；无可验证路径/diff 不补造统计。虚拟资源通信不是文件改动，不能点开不存在 diff。

主/子记录按真实归属恢复，Windows 系统临时工作区的目录编码也要一致。历史运行态不是当前运行证明，详情只读时不应呈现假控制。BTW 主题另从 sidecar 恢复，不能从主 transcript 猜测或自动重发，见[辅助对话](./omp-core-integration#btw)。

## 断线、核心退出与恢复预算 {#failure}

桌面 `desktop-continuous` 与 Web `web-remote-replayable` 使用同一 owner/单调 seq，但语义不同：桌面连续交付；Web 重连按水位续传，缺口取快照。物理帧超过 1 MiB 时分片并校验，不能丢数据换速度。

WebSocket 断开立即拒绝未完成 RPC，页面显示中断并重新连接；发送积压超过既有 16 MiB 阈值要以浏览器合法关闭码结束，不遗留 pending。Host 非预期退出由 Main 通知并重建，旧 Host 迟到退出不能清掉新登记。OMP 崩溃先固化可恢复记录，再终结在途轮/交互。

连续恢复失败最多自动强制快照重连两次。订阅 ACK 或一部分分片不重置预算；只有完整 base 成功校验并应用后才重置。第三次仍无有效 base 应显示错误，不无限重连。恢复后下一 delta 接着已应用水位，不回放副作用。

排查顺序：保存版本、根/Profile、workspace identity、稳定 session ID 与安全错误码；确认是能力缺失、暂不可用、发送失败、等待超时还是核心退出，再查看[关联日志](./logging)。不要先删索引或用户数据。

## 远端与资源生命周期 {#remote}

远端部署使用 `~/.ompcode/server`，不读上游 `.zcode`。HTTP 无鉴权凭据只可监听回环，显式非回环且没凭据应启动失败；不要为恢复绕过鉴权。重连按 workspace identity/owner，不仅看相同路径。

未认领连接超时释放，认领后随 WebSocket 关闭；Docker/WSL 只清各自登记进程。重复关闭、启动换代与 commandId 都须幂等。终端释放失败是生产可见诊断，不应静默吞掉。项目级删除接口仍有 workspace 身份不足的已知限制，目录形状校验不等于任意路径删除完全封闭，不对不可信路径做扩大操作。

## 验收边界 {#evidence}

应观察：首次/续聊/重启只有一个 UUID；文件删除失败不误报；guide/queue 同文逐项消费；源记录读取失败不误删；Web pending 与快照预算真实收口。历史 Windows Chromium、协议、GLM 和冷恢复结果不能替代每种中断时序或当前 GUI 全验收；本站未执行产品验证。

# 子代理、Todo、附件与原生集成 {#overview}

## 跟踪真实子代理 {#subagents}

OMP `task` 启动和调度子代理。GUI 在右上角「智能体」、输入区计数和主对话 Agent 卡片显示真实 ID、任务与运行/结束/失败；点击打开对应只读详情。一次 task 启动多个代理要各自显示，不能以父回复或到达顺序拼成一个代理。已结束目录和胶囊摘要保留，运行计数归零不应让历史入口消失。

实时生命周期/进度与查询快照属于同一会话投影；重启后从父任务归属及受限子记录恢复，不重新执行。结构化 task/wait 或后台自动交付的终态与子 yield/stopReason 要相互核对；历史 pending/running 没有实时 owner 证明时显示「状态未确认」，不算当前运行，也不伪造成功。

详情只读读取不产生模型轮。发送消息/停止仅在父 owner 能证明可控制时开放，并按实际返回显示；它们不是本页观察图的操作，见[核心控制](./omp-core-integration#subagents)及[Agent 交互](./agent-interactions)。BTW 不属于 task 子代理。

## Todo 与工具详情 {#tools}

独立待办面板读取 OMP `todo` 成功结果的完整 phases，同一清单更新替换，pending→inProgress→completed 进度可见。失败/畸形结果不覆盖旧清单，明确空清单可清除。时间线「显示待办」只控制工具行详情，不关闭独立面板；冷恢复及 Web 快照/增量应一致。

通用工具默认显示有效参数和可读结果，不铺开空对象、重复标题或整份调试 JSON。Markdown 按 Markdown，普通文本保留换行且折行，对象/数组或对应合法 JSON 用代码展示；`0`、`false` 是有效值不能隐藏。完整数据默认折叠在「查看原始数据」，按需打开；失败优先展示错误，不用计划正文盖住原因。

`confirm` 必须有接受/拒绝入口并按请求回答，不留无按钮遮罩。`@` 文件选择不应因缺失 ZCode 插件目录报原始不支持错误，文件结果仍可用。

## 附件：上传成功不等于可消费 {#attachments}

| 类型                                           | 提交规则                                                                                              |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 图片                                           | 按原顺序将真实原始字节和 MIME 交给 OMP image content；普通、guide 与 queue 均保留                     |
| UTF-8 文本                                     | text/*、JSON、XML、JavaScript、YAML 等，带文件名并入 prompt；单文件最多 256 KiB，文本合计最多 512 KiB |
| PDF、视频及其他核心不能消费类型                | 提交前明确拒绝整次输入，不静默丢弃或创建空轮次                                                        |
| 不存在、过期、不可读、目录、相对路径或未知 URI | 拒绝整次输入，不回退成空附件；非法 UTF-8 和超限同样拒绝                                               |
| 斜杠命令/BTW 的附件                            | 按对应能力明确拒绝，不把未提交附件附带给原生工具面板                                                  |

桌面选择/拖拽产生的本机绝对路径由目标 Host 异步读取；远端已物化路径也只在目标 Host 读取，不能用客户端同名文件冒充。真实字节准备完成后才发给模型，界面 chip 或路径文字不能证明内容已读取。

上传事务先 begin 固定归属、原始字节数、分片数、SHA256，再 chunk，最后 commit。只有完整片数、精确解码字节和摘要匹配才发布可读 ref；staging 不可消费。少/多字节、缺片、错摘要或跨 session/connection 不得绕过校验。合法重复 chunk/commit 幂等，零字节只能零分片配空串摘要；这些完整性校验不取消类型限制。

首发原生命令不会消费草稿附件，会话提升到 UUID 后仍保留原 File/ref、进度和控制器；随后普通发送必须真正读取附件内容，不仅保留 chip。失败时先记录错误，不靠重新上传隐藏迁移问题。

## 扩展、MCP、浏览器与钩子 {#extensions}

这些页面说明 **OMP 原生配置**，不恢复 ZCode 插件运行时或商店：

- 扩展/MCP 展示当前 Profile、本地项目配置的入口、服务器名、来源与启用态，不展示命令参数、环境或密钥；提供打开配置目录。运行连接状态未由 RPC 提供时标「未提供」，空 `mcp/list` 不是没有配置或已连接。
- MCP 顺序为项目 `.omp/mcp.json` → `.omp/.mcp.json` → 当前 profile agent 的 `mcp.json` → `.mcp.json`，不同名合并，同名先到者生效。禁用同名仍占位，用户级禁用名单优先；文件缺失是合法空来源，读取/解析错误是错误，不吞掉其他有效来源。远端项目不扫描本机目录。
- 浏览器页「默认开启」是说明而非开关，运行配置归 OMP；原浏览器数据导入、清理和证书入口保留，不去查旧 Browser Use 插件。
- 钩子页只枚举 profile agent 与本地项目 `.omp` 下 `hooks/pre`、`hooks/post` 的 JS/TS 文件，不读取/执行源码，不把存在文件说成已加载；只读刷新、打开目录，不提供旧创建/编辑/信任/启停操作。无目录与不可读分别处理。
- Computer Use 使用 OMP 原生配置，不启动 ZCode CUA Helper/broker 或注入其 MCP；看到旧 helper 资源告警不是正常依赖要求。此能力不表示自动获准接管用户桌面。

## 自动化和取消项 {#automation}

自动化调度持久化计划、启停与下次触发，到时通过 Host 创建 OMP 会话。表单模型与聊天目录同源，新任务固定具体 provider/model:effort，采用全权限，无旧权限模式。验收要覆盖创建、立即运行、运行记录、暂停/恢复，保存表单不等于执行。

临时 task ID 的终态先结算自动化记录，再迁移稳定 UUID，后续保持同一身份，侧栏不留两项。换核不能清空自动化计划或运行记录；只可清理旧 CLI 会话投影。

插件/技能市场和安装不可用、市场入口隐藏；回复赞踩隐藏，复制保留；Off-Peak 错峰不可用，其他旧 backgroundWorks 不发起。已有工作流引擎与原生 OMP 编排不是同一能力，见[范围](./fork#limitations)。

## 验收边界 {#evidence}

真实验证应比较主会话、三个子详情、通信页与文件记录，核对 task/wait/后台送达，不只看最终总结。附件协议 fake 验证不代表真实模型图片消费或产品上传 GUI；工具组件的浅深/窄宽结果也不代替真实会话冷恢复。源文档有 Windows 定向附件续发记录，但 CentOS、共享存储和全部图片模型边界仍独立未验证。本站未操作产品。

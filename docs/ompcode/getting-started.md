# 安装与快速开始 {#getting-started}

## 选择正确安装包 {#download}

只从 [OmpCode Fork 的 Releases](https://github.com/jchanghong023/OmpCode/releases) 下载，**不是**上游 ZCode Releases。产品支持 Windows x64 与 CentOS 7 x64；不提供 macOS 或通用 Linux RPM 支持。Windows 与 CentOS 使用独立发布流程，因此不要假设最新一条 Release 同时具有两平台资产。

本次只读核对到以下公开资产，可用来识别正确的文件格式；安装时以所选 Release 实际资产为准，勿根据应用版本相同认定构建相同：

| 平台     | 公开发布记录                                                                                                           | 安装资产与校验文件                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Windows  | [v20261011-225237-38182122443-1](https://github.com/jchanghong023/OmpCode/releases/tag/v20261011-225237-38182122443-1) | `OmpCode-3.14.3-win-x64.exe`、同名 `.exe.sha256`     |
| CentOS 7 | [v20261009-003859-37865830627-1](https://github.com/jchanghong023/OmpCode/releases/tag/v20261009-003859-37865830627-1) | `OmpCode-3.14.3-centos7-x64.zip`、同名 `.zip.sha256` |

下载二进制及**同一发布记录**的校验文件。Windows 可在下载目录用 PowerShell 计算摘要，与 `.sha256` 中的 64 位摘要比较，一致后才启动 EXE：

```powershell
Get-FileHash .\OmpCode-3.14.3-win-x64.exe -Algorithm SHA256
Get-Content .\OmpCode-3.14.3-win-x64.exe.sha256
```

CentOS 7 在两个文件所在目录校验并以普通用户解压：

```bash
sha256sum --check OmpCode-3.14.3-centos7-x64.zip.sha256
unzip -q OmpCode-3.14.3-centos7-x64.zip -d "$HOME"
"$HOME/OmpCode-3.14.3-centos7-x64/bin/ompcode-centos7"
```

::: warning 校验失败就停止
摘要不一致、缺校验文件或缺所需平台资产时，不跳过检查，也不替换成上游安装器。重新获取匹配资产或向维护者报告该发布记录。
:::

CentOS ZIP 不依赖宿主安装 Node、OMP、PRoot 或 root 权限；仍需可用图形会话及必要的系统桌面能力。其 Chromium 沙箱被关闭，Electron 28 与 CentOS 7 均已停止维护，只打开可信项目。启动参数、中文输入和离线边界见[兼容包指南](./centos7-release)。

## 第一个项目与会话 {#first-session}

1. 启动 OmpCode，完成首次引导，打开希望处理的项目目录；先用可丢弃的练习项目，不直接授权代理修改关键数据。
2. 打开「设置 → 模型设置」，确认当前 Profile。OmpCode 不要求旧 ZCode 账号登录；模型目录与认证来自 OMP。安装包包含核心，但**不包含你的可用模型凭据**。无候选时先按 [OMP 配置指南](/omp/)准备可用模型，不在 OmpCode 添加旧供应商账号。
3. 如需更换 Profile，保存后完全退出并重启；待重启时不要继续编辑旧 Profile 的角色。需要长期默认值时设置角色，需要仅本会话变更时使用输入工具栏。
4. 在当前项目新建会话，确认输入区的模型与思考档。新任务默认可能采用该模型支持的最高思考档，并不等于角色配置中的档位。
5. 发送一个边界明确的只读请求，例如「列出这个项目的主要入口，只读分析，不修改文件」。观察正文流式输出、工具过程、错误或完成状态。
6. 再次打开同一会话确认历史存在。列表标题不是稳定身份；首次落盘后应归并为唯一会话 UUID，而不是两个重复任务。

默认 OMP 是全权限运行，不一定出现审批框。需要审批时应先配置 OMP 的审批模式；不能用「没弹窗」判断没有工具执行。首次修改任务应说明允许范围，并保留自己的版本控制或备份。

## 下一步怎么用 {#next-steps}

- 输入 `/` 浏览目标 OMP 的真实命令目录；选中可执行项后提交。未知、仅 TUI 命令及带附件命令会被明确拒绝，不应当成模型问题。
- 输入 `$` 选择[可执行技能](./skills)；输入 `@` 选择项目文件。上传成功不代表模型能读，PDF/视频等类型的[附件限制](./integrations#attachments)须先确认。
- 运行中追加输入时选择「引导」或「排队」；前者影响当前轮，后者等待后续轮，每轮一条，不支持编辑/重排队列。
- 打开输入区「原生工具」，进入项目索引或原生编排页。执行结果和确认仍在原会话，不以面板收到请求回执认定任务完成。
- 查看「智能体」、独立 Todo 面板与 Agent 交互 tab，区分执行事实、只读观察与可用控制。

## 无法开始时 {#troubleshooting}

| 现象                   | 处理方向                                                                         |
| ---------------------- | -------------------------------------------------------------------------------- |
| 找不到内嵌 OMP         | 检查是否完整安装/解压了 Fork 的对应平台包；不要覆盖用户已有 OMP                  |
| 无模型、认证或权限错误 | 检查当前运行 Profile 与 OMP 配置；模型连通性以真实会话结果为准，无旧独立测试按钮 |
| 角色保存冲突           | 保留待选值，重新读取该角色，检查外部配置变化，不强行覆盖                         |
| 历史为空               | 核对实际配置根及 Profile；Linux offline 空 shm 是全新环境，不会自动从备份还原    |
| 命令报不支持           | 看命令目录的能力说明，勿重复以普通文本发送绕过拒绝                               |
| 窗口白屏或进程退出     | 保存本轮版本、平台、脱敏错误和[日志](./logging)；不要把空白窗口当作模型故障      |

安装、模型调用及以上操作未由本次文档工作执行。当前源码与已发布资产可能不同，最新需求的实现存在不表示下载包已包含或已验收。

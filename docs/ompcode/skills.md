# 查找和调用 OMP 技能 {#overview}

## 先打开目标项目 {#catalog}

输入 `$` 的候选、`/` 面板的 `/skill:<name>` 和「设置 → 技能」都取自目标 OMP `get_available_commands` 中 `source=skill` 的可执行条目。设置保留独立技能入口，但它是**只读可调用目录**，不是商店。

1. 打开项目或选择现有会话，确认目标 Host。
2. 进入「设置 → 技能」查看名称与说明；查询失败看加载错误，可刷新，不回落本地扫描伪装成功。
3. 输入 `$` 搜索并选择，或输入 `/skill:<name>` 后附任务参数，再发送。
4. 在会话中核对技能 chip、原始参数和真实结果；完成后应恢复可发送态，冷恢复不应重复调用。

没有打开工作区时显示打开项目引导，不以用户本地文件夹冒充运行时能力。已有会话查询自己的进程，未知会话明确错误；远端只查询远端 Host，不读本机同名目录。

## 共享技能由 OMP 解释 {#shared}

启动环境可选 `OMP_SKILLS_DIR`，存在时作为额外共享技能根，不依赖 offline、配置注册或同步服务。未设置、空值或不存在时保留原来源。共享与个人/项目同名时，GUI 只显示 OMP 选中的共享版本，不自行判断优先级、扫描或计数。

目录进程和会话进程继承同一环境、根和 Profile；已运行会话仍以实际目标目录为准，刷新不能绕过所有权。远端路径必须由远端 Host 环境设置，不能传本机共享路径到远端。

TUI 扩展控制中心可能还列禁用、遮蔽和仅发现条目，那个总数不是 GUI 可执行技能数；比较名称集合而非机械比较两个页面总数。

## 发送的 token 与可见内容 {#invocation}

GUI 发送原生 `/skill:<name>` token，OMP 负责读取技能正文与参数；token 可位于用户句子中间，不重复注入另一份全文。聊天气泡显示技能名 chip 和用户参数，复制仍是原始用户输入。

`skill-prompt` 中给模型的正文、目录提示与包装不会在聊天中铺开。冷恢复优先从核心元数据恢复用户原始调用；旧记录可从 name/args 恢复，元数据缺失也不泄漏技能全文，并保留调用轮次。普通用户/助手文本和普通可见扩展输出不能仅因含「技能」字样被隐藏；agent/autoload 注入不能伪装成用户提交。

## 不能在这里管理技能 {#limits}

OMP RPC 未提供安装、导入、删除与开关时，设置页不提供这些操作，不恢复 ZCode 本地管理或市场。需要变更技能源时按 [OMP 技能方式](/omp/)处理后，重新查询对应目录；不要在 OmpCode 找不存在的安装按钮。

能力故障应区分：无项目、目录为空、查询失败、未知会话、技能不可执行是不同状态。一个会话技能成功不证明另一根/Profile/远端也有该技能。

## 怎么判断可用 {#evidence}

有效证据应从真实目录到 `$`/`/` 选择、真实模型调用、工具结果和同会话冷恢复；只显示两个假候选或组件 chip 不够。共享目录还要核对同名来源与原技能保留。源记录包含展示修复、回归和浅深/窄宽组件证据，但明确未以这些替代完整真实桌面与进程重启验收；本站未重新验证。

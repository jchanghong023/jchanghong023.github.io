# 斜杠命令、索引与原生编排 {#overview}

## 先从真实目录选择 {#catalog}

在目标项目的会话输入 `/`，查看当前 OMP 注册的命令、别名、说明与参数补全。目录会更新，不以本文表格代替运行时能力发现。命令原文、参数与空白交给 OMP；未知、仅 TUI、不支持模式或携带附件时明确拒绝，不把命令偷换为模型问题。

| 入口                                      | 使用目标与边界                                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------------------------- |
| `/wiki`                                   | 原生状态、建立、检索/分页及删除；没有 Wiki 原地更新/重建能力                                |
| `/repo`                                   | 代码索引状态、建立、更新、重建及删除                                                        |
| `/team <任务>`                            | 多模型只读规划讨论；空参数展示核心用法，不承诺执行修改                                      |
| `/plan [任务]`                            | 进入计划模式，使用只读工具与 plan role；查看计划并批准/拒绝，批准后由 OMP 恢复模型/工具执行 |
| `/loop`                                   | 次数/时长、可选间隔及任务由核心处理；裸命令为关闭/切换，不编造 pause/resume 子命令          |
| `/goal`                                   | 创建/替换、查看、暂停、恢复、删除与预算调整，由 OMP 持有状态                                |
| `/advisor`                                | 开关、状态、记录；`configure` 的 TUI 编辑器不支持，角色仍去模型设置                         |
| `/ultrathink` 或正文 `ultrathink`         | 分别按原生命令/魔法关键词处理，正文关键词不是 advisor 参数                                  |
| `/orchestrate`、`/workflowz`、`/fullsend` | 原生编排或魔法流程，不是旧已保存工作流引擎                                                  |
| `/skill:<name>`                           | 调用目标目录的技能，不由 GUI 注入另一份正文                                                 |
| `/compact [参数]`                         | 保留完整参数，过程、结果、错误和用量回投；输入区无独立压缩按钮                              |

删除索引、替换目标和持续循环都有副作用。先确认目标项目与会话、预算及任务范围，按核心确认框操作；不要把示例应用于未备份的工作目录。

## 用原生工具面板，不覆盖草稿 {#panels}

输入区「原生工具」打开同一对话框的两页，先核对页上当前项目/会话：

1. **项目索引**：Wiki/Repo 管理发送裸 `/wiki` 或 `/repo`，随后在会话里的 select/input/confirm 完成维护。不要输入臆造的 `/wiki search`、`/repo build`。
2. **代码检索**：填写非空检索词后，会通过当前会话模型使用 repo 工具，结果进时间线；这会使用模型，不是无模型索引查询 RPC。
3. **原生编排**：选择 Goal、Loop、Team 等，填写参数，核对预览后执行。Goal 常用动作为 set/show/pause/resume/drop/budget；Loop 暂停用既有 Stop，不增加 GUI 定时器。Team/魔法命令只收任务正文，不添加虚构并发参数。
4. 面板直接提交，不是只把命令填进编辑器。已有正文、富节点和附件草稿保留，不自动附带发送。面板关闭不取消已接受任务，停止仍去会话 Stop。

运行中、待问答或队列需要处理时，面板会禁用并说明原因。能力不存在、目录加载失败和模式不支持应可辨认，不能以代码检索或模型提问作隐式回退。重复点击只应接纳一次，切换项目后旧返回不得写入新面板。

## 在哪里看进度与真正完成 {#lifecycle}

所有确认、计划批准、输出、错误与取消仍在原会话中查看。OMP 是索引、计划、团队、目标、loop、advisor 和压缩的唯一业务所有者；Host 不再跑另一套 goal/workflow 状态机。

**ACK 只是接受，不是完成。** 索引和压缩可能先回 ACK，再推迟到输出；没有终态不能推测成功。自动 goal/loop 后续轮也应正常显示工具、回复和真实终态，不需要为显示而再次发送命令。

原生命令输出和可见 custom 结果应在冷恢复后保留；隐藏结果不显示。原生日志尚未落盘的命令派生显示与随后原生历史应去重，但合法同文消息不能被误删。首发命令创建的临时身份绑定 OMP UUID 后，侧栏只有一个任务，草稿与附件都应继续保留。若点选规范 UUID 后草稿丢失，不能靠重新上传掩盖身份迁移故障。

## 验收、错误与历史结果 {#evidence}

正确验收从真实面板进入真实 OMP 到可观察结果，包含空参数、缺能力、取消、失败与破坏性确认；还要观察原生命令首发、保留附件后的普通发送和同根冷恢复。中英、浅深主题及窄窗口只是布局证据，不能代替真实模型或索引执行。

源文档记录过 Windows 原生命令、后续面板和附件链路的定向结果，但明确没有因此逐项重跑所有能力；CentOS、共享存储和发布有独立未验证范围。本站未执行这些产品操作。

# 阅读 Agent 交互 {#overview}

## 打开独立观察 tab {#usage}

主会话显式打开「Agent 交互」，它出现在右侧，与子代理详情 tab 同级，不在主对话内铺整张图。同工作区身份、远端会话和根会话只有一个 tab，重复打开激活已有项。

1. 在正确父会话打开，核对 Main、真实子代理及可证明归属的嵌套代理。
2. 选择一条记录，查看发送方→接收方方向、事件类型、时间依据和正文，图上同步高亮对应节点/连线。
3. 默认阅读短摘要，必要时展开「查看原文」核对完整消息。
4. 切换 tab、收起侧栏或关闭后停止独立查询及动画；重开从权威记录恢复，不会重跑任务。

页面只读，不承担发送、停止、重跑或修改会话；需要干预用[子代理控制](./omp-core-integration#subagents)。

## 认清消息、时间和状态 {#meaning}

- 任务派发、结果返回和代理通信须有真实依据，广播按实际接收者展开，不按代理名单补投递。
- 相同正文、不同消息 ID 保留两条；同一消息在实时、接收记录和转发中的重复观察应归并。发送/回复 ID、方向和可取得的投递结果保留。
- 用户 `steer_subagent` 是用户干预，不冒充父代理通信。投递或唤醒成功不等于已读/已处理，不生成不存在回执。
- 有发送时间才标发送时间；只有记录时间就标记录时间，缺失标未知，不能用恢复时刻代替。
- 冷历史 pending/running 没有实时 owner 证明时标「状态未确认」；明确 task/wait/yield 终态保留，不因根会话结束或时间经过推定子代理完成。

自动后台结果与 wait 接收结果都可关联正确代理，但模型侧唤醒/回复指导不是业务摘要。任务结果优先确定性提取状态、耗时、结果/摘要、子任务结果与报告数量，不调用模型重新概括；代理自己声称发了几条消息不等于真实投递回执。无法识别的内容保留安全原文入口，不伪造语义。

## 查询与缺失怎么理解 {#coverage}

```text
OMP 持久记录 + 已校验实时事件
    → 会话引擎只读交互投影 → Host 查询
    → 仅活动 tab 的补读/轮询 → 图与消息
```

公开读面 `session/agentInteractions` 带 workspace、根 session、分页信息，返回 agents/events/coverage。它是有预算的按需观察，不是独立审计库。切换 scope 后旧请求/进程不能写到新页面，轮询只是刷新频率，不是判断任务完成的时钟。

OMP 当前没有统一全量持久通信日志；仅内存转发或缺文件可能在重启后不能恢复。页面应明确「部分记录」「仍有记录」或未知字段，不能静默截断或把空数据说成完整。查询失败有错误/重试，正常无记录是空态，两者不同。原始消息只作为安全文本渲染，不执行内容。

## 视觉与验收边界 {#evidence}

浅深主题、窄栏、多代理与长正文都应可读；方向不只靠颜色表示。WebGL 不可用或减少动画时保留静态图和同样消息。动画只表现新消息/选择，不无限流动伪造通信。

正确联合验收需要真实主会话创建三个代理、分别执行并广播，逐条对照工具/持久记录，在结束、重开与冷恢复后比较主任务、三详情、交互页的身份和终态。只验证某一截图有文字不够。

源文档记有 Windows 内嵌 OMP/GLM 实时、嵌套代理、tab 生命周期和冷恢复的历史结果；同时保留整仓检查失败与 CentOS、独立 Web GUI、安装包未验收边界。本站未重跑，不视为当前源码/资产全量通过。

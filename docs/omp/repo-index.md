# Repo：当前项目代码定位 {#repo-index}

Repo适合反复查实现、错误信息、配置键及Python定义。建库/查询不调用模型，不要求给Python3.6项目补类型或安装语言服务；仅返回定位候选，**没有调用图、影响分析、测试覆盖、配置消费推断、向量检索或自动摘要**。

## 首次建立和面板管理 {#panel}

进入项目启动OMP，输入`/repo`，核对Root后b、y确认建立。Git项目取当前worktree根，即使从子目录进入也包含全树；非Git取当前工作目录。数据库放用户profile内，按规范化项目根隔离，不写源码目录，不混不同worktree。

| 面板按键 | 操作                                         |
| -------- | -------------------------------------------- |
| b→y      | 首次确认建立                                 |
| u        | 完整枚举/读取/内容指纹核对，未变文件不重解析 |
| r→y      | 重建，坏库/schema不兼容可恢复                |
| d→y      | 删除索引不删源码；先停在途建库避免复活       |
| c        | 取消建/更新/重建                             |
| Esc      | 关闭；操作中先确认取消并关闭                 |

可看文件/符号数、代次Generation、Coverage、Pending、Failures、未核对原因和Last full check。失败/取消不发布半成品，旧可用代保留并标不确定。AI查询不能替用户确认首次建库。**没有omp repo终端命令组**。

## AI查询与分页 {#queries}

正常对话可说“用repo定位配置读取候选，再读当前文件确认”。工具只有query/action/path/cursor四参数，默认search；这些是AI参数，不是终端命令：

```json
{ "query": "timeout", "path": "src" }
```

```json
{ "action": "symbol", "query": "ConfigLoader.load" }
```

```json
{ "action": "status" }
```

search给文件/类别/原始行号/有界片段；symbol仅Python模块/类/函数/方法定义、限定名和可用签名；status给代次、覆盖、待更新、失败，不扫描源码。每页最多20条，cursor绑定动作/查询/path/代次，省略action等价search；代次变了从第一页重查。普通搜索不重复完整状态，但不能隐藏pending/unchecked/failure提示。

path须根内相对，Windows分隔符可归一化；根内..可接受，绝对、盘符相对、越界拒绝，不假装零命中。POSIX若真有含反斜杠文件优先字面路径，否则按Windows分隔规则。无索引、零命中、坏库/查询错误区分，均不证明仓库无代码。

默认非受限xdev模式先read xd://repo看schema，再write xd://repo传JSON；关闭xdev仍顶层工具。独立repo审批不继承write拒绝/询问，可共享并发，显式受限工具清单不扩大。

## 什么会入库、匹配如何工作 {#contents}

```text
枚举/分类/指纹 → 原始文本与行号 → Python定义解析 → SQLite文本/符号索引
```

遵循Git忽略及文件搜索规则，可包含范围内隐藏文件；不跟符号链接，二进制、无效UTF-8、超2MiB、不可读文件排除或报告。类别是定位标签，不是访问控制或测试覆盖证明。Wiki是另一个手工Markdown数据库，不共享生命周期。

Python用内置Tree-sitter支持装饰器/嵌套/异步等3.6风格，**不做名称绑定/类型/引用解析**。同名靠路径/限定名/行号区分。解析失败含空或仅注释语句块时保留可用文本、清过期定义并记失败；当前grammar对Python3.6软关键字函数名仍有限制。其他语言只文本定位。

文本以JavaScript toLowerCase不区分大小写字面找，完整边界优先、其次子串/词元补召回，timeout可找ERR_TIMEOUT；短于3字也有路径。不是正则或SQL语言，不保证所有出现位置。较早子串不遮较后完整匹配，组合附加符不算完整边界。symbol按名称/限定名不敏感子串找。

页内读正文生成片段，有界定位缓存不存全源码；文本/符号同一SQLite读快照，可取消不发布部分查询。维护独占锁期间读已发布代次，不等整轮重建，保留pending/unchecked；锁放后再处理路径，不吞错误。

## 更新与当前性 {#updates}

| 变化                               | 处理                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| OMP成功编辑/新建/删除/重命名       | 记路径（重命名旧/新），下次search/symbol局部合并处理         |
| bash/eval                          | 标可能影响范围未核对，不凭命令文本猜具体文件                 |
| JCH改树Git命令                     | 改树步骤一开始即标未核对，部分失败也标；只读fetch/status不标 |
| 启动/切会话、Git HEAD/worktree线索 | 标未核对，低成本提候选，不等于完整核对                       |
| 外部编辑/批量文件/忽略规则变化     | 不保证即时发现；面板u完整核对                                |

完整核对必须遍历并读指纹，能发现同大小同mtime与未跟踪新文件；内容不变不重解析。扫描前后核清单/内容，期间未通知变化失败保旧代，已通知新变化留pending，不能假已核对。文件被目录替换时清旧文件记录并处理发现子文件。强杀留下的未发布代在下次独占维护锁回收，不删当前代/源码。

Last full check只说明当时完成，不证明之后没改。需要穷尽/当前结论回到真实文件和已有工具，不每次查询全扫，也不把旧结果当最终真相。

## 日常分工和故障 {#workflow}

- 找实现：Repo候选→read当前源码；编辑前必须复核当前行。
- 文件名/路径：glob；全部出现位置/正则：grep。
- 调用方/类型/语义影响：可用LSP及源码；Repo没有这类结论。
- 语法写法：可用只读ast_grep；结构修改先读xd://ast_edit，它不是只读。
- 已知小文件直接read，不强制绕索引。

缺索引可提示/repo建立并退现有工具，不能阻断普通开发；坏库在面板重建，不能假零命中。旧解析器误报定义需显式重建，不保证自动修旧全部符号。

## 证据和验收边界 {#validation}

源记录有真实SQLite、Python解析、本地CLI/TUI和故障保全证据，含部分AST写入后刷新仍unchecked、完整核对才解除；模型替身不证明真实模型任务成功率。合成基准不代表公司源码/NFS/权限/多机性能或定位质量。当前接口真实TUI、Linux及企业环境缺口仍须逐源码看源索引。

维护入口包括coding-agent的repo-index/repo-lifecycle/repo-tool测试、natives的python-symbols测试、scripts/repo-ui-smoke.ts和repo-index-perf.ts，真实TUI纳入fulltest且仍受当次授权。验收应覆盖三动作、path/cursor、短查询、增量/全核对、失败取消旧代、删除不动源码、真实面板到结果链路；入口存在不是执行通过。本站未运行这些检查。

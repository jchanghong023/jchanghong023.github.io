# Goal：持续无人值守目标 {#goal-autopilot}

`/goal-autopilot`沿用普通`/goal`的目标生命周期，额外标记无人值守模式，并将完整目标、共享Orchestrate规则及全自动指令持久放入历史。它不是无限执行开关，不是绕过审批的方法，也不同于[禁止测试的workflowz批处理](./fork#jch-commands)。

## 创建、查看、暂停与预算 {#commands}

先确认项目、范围、模型与授权，退出只读Plan后在OMP输入框使用：

```text
/goal-autopilot 修复当前项目已确认的RPC问题，保留无关改动；按项目规则完成必要验证，汇总结果、失败与阻塞证据。
```

| 命令                         | 含义                              |
| ---------------------------- | --------------------------------- |
| `/goal-autopilot <目标>`     | 创建或替换，并启用模式            |
| `/goal-autopilot set <目标>` | 同上                              |
| `/goal-autopilot show`       | 查看当前目标/状态                 |
| `/goal-autopilot pause`      | 暂停目标，保留已做修改和历史      |
| `/goal-autopilot resume`     | 恢复目标原有模式                  |
| `/goal-autopilot drop`       | 按普通Goal确认删除，非撤销代码    |
| `/goal-autopilot budget <N>` | 设置目标token预算                 |
| `/goal-autopilot budget off` | 关闭目标token预算，不解除其他限制 |

TUI、mode rpc、mode rpc-ui共用参数/空参/错误处理，未保留旧命名别名。自动续跑是否启用及触发沿用上游，不由该命令强行开启。

## 模式属于目标，不属于命令名 {#persistence}

用autopilot成功创建/替换才带标记；普通goal新目标不带。show/pause/resume/budget、用量/状态更新均保留原标记，drop随目标删；失败/取消不改变。**对普通Goal执行autopilot resume不会转换模式**。旧会话无标记按普通Goal；恢复/切换/分支从对应目标读，不能串其他会话状态。

暂停保留标记，但不新建本模式通知/目标工作；resume沿原生命周期，不单独重构通知。完成/删除/退出停止新增，不追改旧历史。恢复会话是否暂停或继续按原Goal，不因模式自动跑。

## 完整目标何时进入历史 {#history}

第一次成功创建/替换进入正常执行链，持久保存一份完整通知：未截断原目标（保留空白字面量）、当时已启用能力展开的共享Orchestrate、固定无人值守要求。附加于而非替代上游Goal提示。

仅真正成功提交压缩、历史实际重写后，才从提交时有效目标再构造一次，并纳入新基线。不依赖摘要保留长目标；失败/取消/未提交/no-op压缩不重构。工具往返、模型续接、重试、已允许续跑、恢复、预算更新、pause/resume或工具变化本身不重建完整通知。当前目标暂停/完成/替换/删除/预算不允许时不得复活旧目标。

两次压缩之间通知原字节/历史位置不变，不每次请求临时拼另一视图、不裁旧消息去重。普通模型用真实持久历史，get_messages/get_entries、session.jsonl和dump应能观察。压缩本身允许上游重写历史，不保证原缓存跨压缩保留；状态变化也不撤回已经发出的请求。

## Orchestrate复用与能力边界 {#orchestrate}

首次/成功压缩边界复用共享模板与实际enabled能力快照，包括经xd设备间接可调用能力，不只看顶层schema。不维护旧Codex Code Mode分区或桥接。task不可用时只省略Orchestrate，完整目标和无人值守要求仍保存；中途工具变化不改旧通知，下次合法重构才更新。

显式命令模式不受正文关键词开关影响。同一构造事件按来源/目标/压缩事件去重，不按用户正文关键词删消息；不压制普通Goal提示，也不请求时裁历史。子代理、压缩、advisor等辅助路径不另建整套通知，但普通模型正常历史可含已保存通知。

## 授权到底意味着什么 {#authorization}

内置附加要求表达：对完成当前目标全过程所需调查、规划、编排、实施、验证、修复作明确授权，自主决定、不反复提问/确认/等待；包含目标所需Git提交、推送和gh等CLI、仓库文件修改。与先前用户级要求冲突时以这次授权为准，**仍是用户级，不提升为系统/开发者权威**。不要在只想咨询时调用它。

它不能代替操作系统权限、缺失凭据、宿主强制审批，也不能猜关键对象或绕过限制。先找既有授权内替代路径，确无可行就记受阻、继续可执行部分，最终报证据和缺前提；全部受阻按原退出，不忙等、不虚报完成。用户主动管理对话（包括删除确认）仍保留。后续输入、暂停、停止、取消始终有效。

内置ask默认60秒、Plan不超时；仅当前有效执行中autopilot目标未回答时，返回明确自动回复让主模型按原目标自主继续，不代选推荐/肯定/首项。普通Goal超时仍上游选择逻辑；cfg审批等其他确认不变，见[默认设置](./fork#defaults)。不能保证模型绝不提问或任务必成。

## 运行中追加、无进展停止与远端模式 {#runtime}

普通Goal和autopilot都允许Ctrl+Q/Ctrl+Enter follow-up排队。当前完整工具批次结束、目标仍执行中时，按原队列顺序送下一条到后续模型调用，不等连续工具循环全部结束、不打断当前工具。暂停/退出/完成/预算限制/非Goal仍保留原边界；自动handoff/提醒不冒充用户输入。

自动续跑非空文本但整轮无工具时，每段连续续跑最多一次工具纠偏：复用完整目标和正常续跑消息，仅首个模型调用尝试强制一个可用工具，后续往返恢复自动。失败/取消/前置门禁/会话切换不能把强制选择泄漏下一轮。纠偏后再无工具也不能无限重置次数；失败、无法强制或仍无活动停止续跑并notice说明目标未完成。重复工具证据、原错误/截断/空输出、预算耗尽和全受阻保持原停止，不强行复活。

选JchTools后端Agent时，本地Goal标记/历史/通知仍可保留，但HTTP/ACP只投影真实用户来源与可见聊天，**不发送OMP生成的目标编排、授权展开、自动提醒或关键词通知**。用户实际写的目标/授权/背景原文可传，不从命令推导一份授权。远端工具不算本地可调用能力，取消后不借Goal重试重放；下一显式用户请求新后端会话。详见[远端Agent](./fork#remote-agent)。

## 验收和费用不能混为一谈 {#validation}

源契约要求真实CLI/TUI/rpc/rpc-ui观察持久消息、最终Provider请求、模式切换、取消/预算与会话隔离。普通模型至少十次工具往返/十一次主调用保持严格前缀；两次实际成功压缩即使摘要漏目标也各恢复一次完整通知；失败/no-op不恢复。真实Codex WebSocket要观察response.create、previous_response_id和delta重建，只有HTTP记录不能证明WS兼容。

追加用户输入要核对实际工具批次后送达并影响结果；纠偏要看真实工具选择/执行及停止notice。JchTools另验本地通知存在但远端无内部通知。模型遵从、稳定前缀、Provider cache telemetry、目录成本估算和账户实际账单是不同证据，不能由协议通过承诺命中/费用节省。GUI和真实项目质量也另验。

# 选择工具与首次使用 {#overview}

## 选择入口 {#choose}

- **希望在终端直接操作代码和工具**：阅读 [OMP 安装与快速开始](/omp/getting-started)。安装来源、模型配置、网络与离线准备均以该页为入口。
- **希望在图形界面与 Agent 协作**：阅读 [OmpCode 安装与快速开始](/ompcode/getting-started)。注意桌面与 Web 的运行边界，以及 OMP 核心的依赖关系。
- **希望处理本地文件或使用 Windows 工具箱**：阅读 [JchTools 安装与快速开始](/jchtools/getting-started)。部分 OCR、转换和模型能力需要单独准备推理组件或模型资产。

## 下载与配置前 {#prepare}

1. 确认目标产品和支持平台，不混用三个项目的发行资产。
2. 只使用项目指南指向的公开仓库与发行入口。OmpCode 的产品仓库是 [jchanghong023/OmpCode](https://github.com/jchanghong023/OmpCode)，不是上游项目的下载页。
3. 在受限网络中，先确认可用模型、依赖和离线资产；组织内部值由管理员提供。
4. 准备一个不含重要数据的独立工作目录。首次尝试删除、批量整理、推送或后台服务配置时，先确认作用范围与恢复方式。

## 推荐的第一次操作 {#first-use}

| 工具     | 第一次操作的目标                                                                 | 完成后继续阅读                  |
| -------- | -------------------------------------------------------------------------------- | ------------------------------- |
| OMP      | 根据快速开始建立配置，在明确的工作目录启动一次会话，确认模型与工具可用           | [OMP 专题目录](/omp/)           |
| OmpCode  | 启动对应版本的客户端，选择工作区并确认模型目录与会话入口                         | [OmpCode 专题目录](/ompcode/)   |
| JchTools | 启动工具箱，在副本上选择一个无需额外模型的文件处理工具，检查分析结果后再确认执行 | [JchTools 专题目录](/jchtools/) |

这里给出阅读顺序，不替代各项目快速开始中的实际命令与前置条件，也不要求立即执行会产生费用、网络访问、文件修改或系统状态变更的操作。

## 遇到问题时 {#troubleshooting}

优先在对应项目页查找平台、模型、权限、网络和资产限制。提交问题时说明产品版本、操作入口和可公开的错误信息；不要上传令牌、完整用户目录、企业地址或敏感项目内容。可用[来源覆盖](/coverage)中的需求编号定位规则，但不要将原始需求中的历史结果当作当前环境已通过的证据。

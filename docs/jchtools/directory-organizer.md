# 目录整理：先看计划，再改变资料 {#directory-organizer}

目录整理负责去重、一级归类、命名与清理，不自动解压。首次使用应选资料副本；默认删除是永久删除。即使选择“保留文件”，归类、改名和实际空目录清理仍会执行，没有回滚。

## 分析与授权计划 {#workflow}

C-01、C-11：选目录 → 调整规则 →「开始分析」→ 分页查看计划并逐项勾选 → 确认执行。分析只读，不改资料；只有计划就绪可以执行，显示源路径到最终目标的一项完整处置，不把相互依赖的中间改名伪装成独立授权。

第一次建议先把全局删除改为“保留”，再确认系统附属、临时备份、零字节各自有没有显式“永久删除”覆盖。检查计划是否符合自己要的一级结构，不认可的行取消勾选；不是必须把所有行执行完。

分析顺序固定：识别范围/保护树 → 计算清理条件 → 在保留文件中判重 → 确定最终名称/扩展名/大类 → 全目标消解冲突 → 形成计划。清理待删项不当去重保留者；待删副本不再生成移动。一个文件命中多条删除只删一次，计划列实际导致删除的原因。任一启用清理项请求永久删除就会形成删除，另一个项的“保留”不否决它；取消该删除行才取消该文件全部清理请求。

取消勾选后原位置成为占用；依赖已取消移动的副本删除不能继续。程序用已有分析资料重新计算受影响计划，不新读正文、不自动多勾行，目标变化应展示后再确认。没有文件动作也可能仍需清理范围内空目录。规则或目录变更后旧计划失效，必须重分析。

任务状态分分析中、计划就绪、执行中、完成、失败、已取消；行状态有待执行、已执行、已跳过、已取消勾选、执行失败。分页只在确有该页时可用，类型筛选回第一页。

## 去重不是按名字删文件 {#dedup}

C-02～C-04：默认同名和副本名去重开启，不同名关闭。先同尺寸，再按原完整名/剥副本尾标记的名称键建立候选连通组，最后以**完整内容哈希一致**确认重复。不同名开启时同尺寸都可成为候选；同名内容不同不能淘汰。哈希不可得则保留、说明原因，不凭名称或尺寸删除。

默认留修改时间 mtime 最新者，可选最旧或最短完整文件名（含后缀）的 UTF-16 单元数。有效 mtime 排在缺失时间前；平局先原相对路径长度，再稳定路径升序，不由扫描或线程顺序决定。没有最大/最小保留者，因为内容相同的大小相同。

副本只提供保留或永久删除，默认随全局永久删除；不创建硬链接替代。可靠标识证明两路径已是同一物理文件时保护，不把它们当独立重复副本；标识退化不随意跳过去重。

C-12、C-13：一次整理每个需要哈希的文件最多一次完整读取，执行阶段复用分析结果，不采样、二次哈希或删除前逐字节复核。跨运行缓存以文件标识、大小、mtime 三者一致复用，信任时间未变即内容未变；失效/不可读/写失败则正常重算，不影响检出范围。隐藏修改时间的外部改写不在防御范围，处理期间也不监控其他程序改文件。

## 清理、保留与固定容器 {#cleanup}

C-07～C-10：成功结束前自底向上删除实际空目录和空目录链，保留根、Git 排除树；没有开关，不能递归删有内容的目录。取消后不启动后续删除，清理失败不冒称完成。不会清理用户排除树或非递归未纳入后代。

| 规则               | 默认与精确命中                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 系统附属文件清理   | 开；完整名 Thumbs.db、.DS_Store、desktop.ini 或前缀 `._`；`__MACOSX` 目录内范围内普通文件逐项列计划，不直接整树删除 |
| 临时/备份清理      | 关；最后后缀 .tmp/.temp/.bak 或完整名以 `~$` 开头，不匹配主体中间字符串，不按目录名递归删除                         |
| 零字节清理         | 关；逻辑长度正好 0，不是非空但内容全零                                                                              |
| 副本后缀清理       | 开；末尾 `(N)` 转 `_N`、Copy/副本移除，保留复合后缀                                                                 |
| NFC 与连续空白     | 开；两个行为共用一开关，只作用主体                                                                                  |
| 内容签名修正扩展名 | 关；确定格式才修改，并列入计划，无法确认不猜                                                                        |

前三项可各自覆盖全局删除方式。零字节清理若永久删除，允许整组空文件全删，不受“去重至少留一份”约束。只选保留不禁止其他启用规则归类/改名。

任何「解压失败」目录整树固定保留，不参与去重、分类、清理文件或 Git 集合移动，包括手动放入内容；不因名字去查历史。必要目录项检查确认实际为空时可清空目录链，但不能进入 Git/链接边界。待重试归档应由用户移出后用解压工具处理。

## 一级归类与完整扩展名映射 {#mapping}

C-05、C-06、附录 A：目标固定在所选根下，普通文件为“大类/文件”，不保留原层级，没有年份/月/语义/功能二级目录。只按**最终扩展名**分类；不读取正文、metadata、文件名语义，不用模型/Embedding/聚类。扩展名匹配不区分大小写，最长复合后缀优先；只有显式签名修正可先改变后缀。

| 视频   | .mp4 .mkv .avi .mov .wmv .flv .webm .m4v .mpg .mpeg .ts .mts .m2ts .3gp .vob .rm .rmvb                                              |
| 音频   | .mp3 .wav .flac .aac .m4a .ogg .opus .wma .aiff .aif .ape .mid .midi                                                                |
| 图片   | .jpg .jpeg .png .gif .bmp .webp .tif .tiff .svg .ico .heic .heif .avif .psd .raw .cr2 .cr3 .nef .arw .dng                           |
| 文档   | .pdf .txt .md .rtf .doc .docx .docm .xls .xlsx .xlsm .csv .ppt .pptx .pptm .odt .ods .odp .epub .mobi .azw .azw3 .chm .html .htm    |
| 压缩包 | .zip .7z .rar .tar .gz .bz2 .xz .zst .lzma .z .tgz .tbz2 .txz .tzst .tar.gz .tar.bz2 .tar.xz .tar.zst .tar.lzma .tar.z .lz4 .br .lz |
| 程序   | .exe .com .msi .msix .appx .msixbundle .appxbundle .bat .cmd .ps1 .apk                                                              |

`.ts` 固定归视频、`.raw` 固定归图片，不猜是不是源代码。可识别 X-10 分卷归压缩包，孤立 `data.001` 仍是其他；分类不保证分卷整理后仍同组可直接解开，故应**先解压，再整理**。映射不能自定义，不扩大解压白名单。

唯一附加项“大文件单独归类”默认关，默认阈值 1 GiB，等于也命中；命中优先落“大文件/文件”，不重复到另一类。Git 和排除项不参与。移动保留创建/修改时间。旧年/月或功能层级按普通来源处理，搬空才清理，不能移动有内容目录强制折叠。

## Git 项目整体归类 {#git-projects}

C-14、H-06：根及祖先带 `.git` 时拒绝整次；子项目作为整体平移到本次根下「Git项目集合」，不读内部、不哈希、不改名其中任何文件。只允许不遍历树内的同卷目录移动，跨卷保留源并失败；不复制半项目后删除原件。

项目目录名整体当主体，冲突使用下节相同来源/路径摘要规则，但不清理项目名的副本标记或修正后缀。已有项目在本次根集合内就不重移；整理父根时可把子根旧集合项目聚合到父集合，不能集合自嵌套。无项目不预先建容器。固定容器被文件/Git/链接占用不挪走占用项，不换名字，相关项目保留报错。

## 冲突命名为什么这样变化 {#naming}

C-16～C-20：先按开启规则规范化，再按**整个最终目标目录**共同消解。`报告 (1).pdf` 与 `报告_1.pdf` 规范化后同名也会冲突；不同大类互不冲突。没有冲突的文件不加前缀、不加哈希。

1. 多个新项同名时统一加最少必要来源段，不是先到者留原名。例如 `x/合同.pdf`、`y/合同.pdf` → `x_合同.pdf`、`y_合同.pdf`。
2. 从最近父目录逐级扩展至唯一，如“正式版”仍冲突，就加“客户”，再加“地区”。紧邻的标准大类/大文件段剔除，本次根剔除；更深只是恰好同名的普通段不乱删。项目的直接 Git 集合容器同样剔除。
3. 一个已就位项可占规范化原名时优先保护，让新移入项退让；多个已就位项本身冲突也统一消解。不参与动作的文件/目录永远优先，不能腾走它们。新候选还需避开其他冲突组的候选与全部保留项，不只看原组。
4. 来源用尽仍冲突，使用最近有效来源 + 主体 + 路径短摘要；SHA-256 输入为分析时原相对完整路径的无 BOM UTF-8，统一 `/`，保留原大小写/Unicode，不做名称清理，默认大写前 8 位。它是**路径摘要，不是内容哈希**。仍冲突每次延长 2 位至 64，最终按原路径稳定顺序加 `_1` 等序号，有限退让失败则保留源。
5. 冲突候选超过 40 UTF-16 单元立即退让为“主体前段_摘要.原后缀”，去掉本轮新增来源，主体先至多 25 单元再按需要截短；不切代理对、不截后缀。40 是退让阈值，不是所有文件强制上限；单段 255 是硬限制，完整路径还需文件系统实际可用。不能合法容纳就失败。

合法化与副本名精确语法见[共用名称规则](./contract#names)。旧前缀属于当前主体，不能反向猜已消失的历史目录。例：上次已是 `客户_合同.pdf`，父目录重新汇总发生新冲突可成为 `分组_客户_合同.pdf`；没冲突的旁边文件不为整齐而改名。

## 最小改名、幂等和停止 {#idempotence}

C-10、C-15、C-21：同一根、规则和资料未变，完整成功后重复整理，目录/位置/名字/项目位置均应不变，不新增哈希、不套“文档/文档”或“Git项目集合/Git项目集合”。已就位文件仍需应用显式开启的清理规则；规范化造成真实冲突不是幂等豁免。

先整理子根再整理父根会重新汇总，名字可能与一趟处理不同，因为可用来源已改变；不要求不同整理历史逐字同名。最终普通文件一级、项目平铺、搬空中间目录消失；排除、取消勾选和失败留下内容时不得强删强凑形态。

取消是安全边界停止，不算错误，不继续删除；已执行移动/永久删除保留，未完成项如实显示。再次运行是新分析而非恢复旧计划。跨卷复制/时间设置/源删除失败、路径不可用、固定容器被占用都应保留能保留的源项并显示具体阶段；没有已执行产品测试的前提下，不应把上述预期写成性能或安全验收已通过。

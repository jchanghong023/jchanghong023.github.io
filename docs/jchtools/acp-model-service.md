# 模型服务：HTTP 调用外部 ACP Agent {#acp-model-service}

模型服务把用户已经安装的 ACP Agent 接到本机 OpenAI 风格文本接口。它不是 JchTools 自己的模型推理器，也不是截图/Xberg 后台，更不是所有工具的 HTTP 自动化入口。

::: danger 后端 Agent 可以执行工具
权限按 Agent/ACP 提供的最大授权自动处理，GUI 不逐次审批。后端可能读写工作目录、执行命令、使用网络工具，并把提示及读到的资料送给其模型服务。只向自己可信的本机调用方和 Agent 开放专门任务目录，不用私人唯一资料做试验；回环监听不等于工具执行无风险。
:::

## 责任边界与支持接口 {#scope}

AH-01～AH-05：请求链是 HTTP 调用方 → Axum HTTP 后台 → JchTools 适配层 → 官方 Rust ACP 客户端 → 外部 Agent，结果反向返回。Agent 是 ACP 服务端，负责模型认证、系统提示、skills、工具决策和执行。JchTools 不接管账号、不直接调用供应商模型 API；并不承诺离线。

HTTP 只提供 `GET /v1/models`、`POST /v1/chat/completions`，支持普通 JSON 和真正增量 SSE；没有 Responses、Embeddings、媒体或客户端工具循环。输入角色为 system/developer/user/assistant 的字符串或纯 text 内容块；图片、音频、工具消息、`tools`/`tool_choice` 和未映射的非空能力选项明确拒绝，不能静默忽略。

system/developer 在 ACP v1 只是用户消息中的带角色背景，不具备替换 Agent 原生系统提示的权威。多消息初始化保留角色和文本；只新增一条 user 时原样传 ContentBlock，不加 role prefix/通知包装，以保留 `/web ...` 等 Agent 原生 slash 前缀（是否支持命令取决于 Agent）。OMP 接入只当文本/SSE 客户端，不注入前端自己的 system、工具 schema、skills 或内部通知；这不表示其他调用方的合法背景应全被删除。

## 准备 Agent 与第一次配置 {#setup}

1. 自行安装支持 ACP 的 Agent，在它自己的流程中完成模型认证与必要配置；程序不随 JchTools 提供。不要把真实凭据粘到公开文档或 JchTools 启动参数里。
2. 进入“模型服务”，程序栏填写真实可执行文件路径（不包外层引号），参数栏单独填参数。参数按 Windows CRT 引号规则解析，不简单按空格拆；空格/制表符分隔，中文和带空格参数需正确引号。
3. 选择空闲端口，默认 **8765**，仅 1～65535 整数，监听固定 **127.0.0.1**，不接受局域网。占用/非法/命令缺失/ACP 初始化失败直接报告，不偷偷换端口。
4. 保存后异步启动或连接独立后台，等实际就绪再发请求。没有有效配置时只显示未就绪，不阻塞其他工具。

现行需求真实验收基准是 OpenCode；其公开启动方式 `opencode acp` 对应程序栏实际 opencode 可执行文件、参数栏 `acp`。不要凭空加 `--model`、`--thinking` 或 `--approval-mode yolo`，源码记录该基准帮助不提供这些参数。其他 Agent 需按自己的公开能力，不能套用名称推断兼容。

AH-08、AH-09：程序/参数/端口保存在应用 SQLite，保存失败保留原值。运行中保存新值不打断现有服务，显示“待应用”；用户点“应用并重启”后停接新请求、等待已接收请求结束再换配置。模型/推理等级可由 Agent 自己的真实参数决定，不增加 GUI 工作目录配置或供应商账号管理。

## 读取模型并发送文本 {#http}

先在服务实际显示的地址查看模型；只有使用默认端口时下列回环地址才正确：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/v1/models'
```

Models 只公布 Agent 协商确认可选择的真实 ID，不编固定别名、不把 Agent 内部所有模型都算可用。ACP 无创建时间时 `created: 0` 是协议兼容值，不代表真实创建日期。没有模型选择能力就明确不可用，不猜凭据已就绪。

每次 Chat Completions 顶层必须给 `cwd`，它必须是当前任务的非空、已存在、绝对目录；缺失、相对路径、文件路径或不可用均 400。路径由调用程序获取，不让用户把它写进提示正文。

以下 PowerShell 示例仅在**已就绪且使用默认端口**时适用：先把终端当前目录切到自己准备的非敏感专用任务目录，再执行。它会选择实际 Models 响应中的第一项并发出一次真实后端请求，可能使用 Agent 的网络、工具或模型额度；不确定第一项模型是否符合预期时不要运行，先在客户端选择明确目标。本站没有执行此示例。

```powershell
$base = 'http://127.0.0.1:8765'
$models = Invoke-RestMethod -Uri "$base/v1/models"
if (-not $models.data -or -not $models.data[0].id) { throw '服务未返回可选模型' }
$body = @{
    model = $models.data[0].id
    cwd = (Get-Location).Path
    messages = @(@{ role = 'user'; content = '请仅回复一段简短中文说明' })
    stream = $false
} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "$base/v1/chat/completions" -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

此例使用普通 JSON；需要 SSE 的客户端把 `stream` 设为 `true` 并逐事件读取响应。

流式返回应在 Agent 完成前看到文本增量，再收到结束标记，不是把整段完成结果切成伪 SSE。HTTP 只返回文本，Agent 工具事件不变成要求 HTTP 调用方执行的 OpenAI `tool_calls`。

## 会话、工作目录与并发 {#sessions}

AH-04、AH-06、AH-12：默认每次请求新建 ACP 会话并送完整历史。要续会话，把响应 `X-JchTools-Session-ID` 回传，并提交含上一轮实际 assistant 输出的完整一致历史，服务只提交新增部分；历史前缀不一致拒绝。会话绑定首次规范化 `cwd`，在途/等待轮次也受约束，换目录需新会话，跨目录续用 400。

业务 `session/new` 用调用方目录，不修改进程全局 cwd；终端回调没带 cwd 时取所属会话目录，显式带时用指定绝对目录。Agent 进程初始与只用于模型探测的会话在应用状态目录工作区，不能把探测会话复用成其他任务目录业务会话。

一个后台、一个官方客户端、至多一个常驻 Agent，不为每请求起进程。独立会话可并发，同会话按接收顺序串行，不用后轮隐式取消前轮。最多 4 执行、16 等待（同会话等待也计容量），满返回 429。不支持真实多会话并发的 Agent 应报告限制，不能多起 Agent 或把排队叫并行。

来源 README 还区分：prompt 发布前取消且安全收尾可保留会话，已排队后轮仍可执行；发布后取消会使该会话失效，后续需新会话。调用方应按实际服务错误处理，不能自动重放可能已执行工具的旧任务。

## 权限、文件/终端回调与取消 {#permissions}

AH-13：按 Agent 公开方式启用其支持的最大授权/免审批；收到 permission 回调选择最宽允许项，优先“始终允许”，GUI 关闭也不等人工。无允许选项或必要能力就失败，不伪批准；非权限交互也不编造答案。最大授权只到当前 Windows 用户已有权限，不提权、不 UAC、不绕过 Agent 固定策略或系统限制。

Rust 客户端实际承接宣告的文件读写、终端创建/输出/等待/释放等回调并传回结果或错误，不推给 HTTP 调用方。终端省略输出限额时保留末尾最多 1 MiB；显式包括 0 按 Agent 值，截断保持 UTF-8 并报告 `truncated`。这是本客户端策略，不是 ACP 默认。终端主命令退出不保证仍持管道的后代全结束，释放/后台退出负责自有资源收尾。

HTTP 断连仅取消对应轮次，不关唯一 Agent、不影响别的会话。Agent 连接断裂使受影响在途请求失败；下个新请求可重建唯一 Agent，不重放旧任务。Windows 对端关闭观察存在内核查询失败的现实边界，查询告警不等于证明断连，不承诺任何管线缓冲情况下瞬间检测。

## 后台、发现与退出 {#lifecycle}

AH-06～AH-10：服务在当前 Windows 用户会话独立进程，持有 HTTP/ACP/自有 Agent。关闭或终止 GUI 不停监听、不取消在途或后续请求；重开连接原实例。没有默认增加登录自启，不把其他文件任务变成关窗继续跑。

主动退出从模型服务页单独确认，停接新请求、请求级取消、安全等待，释放自己的 Agent/终端/连接，不自动强杀无关进程。它不归截图/Xberg 托盘退出，也不新增托盘；退出后本次 GUI 不自动拉起，下次重开才按配置启动。配置 Apply 排空中也能提出 Stop，退出意图不能被迟到的 Apply 撤销。

AH-15：同用户、同登录会话可经已有控制命名管道只读 Discover，返回版本、`jchtools-acp-http` 服务标识、实例、实际阶段、`server_agent` 模式、文本/流式/服务端工具能力。仅实际 ready 时给真实端口 base_url，未就绪为 null；后台不存在只报告发现不可用，不启动 Agent、不读配置猜端口。响应无启动命令、参数或秘密，同后台实例 ID 稳定、重建后改变。

AH-16：服务给自己启动的 Agent 子进程固定 `OMP_JCHTOOLS_DISCOVERY=0`，仅影响继承链，避免后端 OMP 再发现自己递归；不改系统/用户环境或持久配置。普通 [OMP](/omp/) 可发现实际服务并显示后端 Agent 模型，自动传当前任务目录，但 OpenCode 验收不证明 OMP UI 发现能力已验证。

## 实现选择与源码交付边界 {#implementation}

AH-02、AH-11、AH-14：HTTP 用 Axum 0.8.9，ACP 用官方 `agent-client-protocol` Rust SDK 公共客户端接口，SDK 包版本不是协商协议版本。不自建 HTTP 网络栈/ACP 实现或移植推理模块，不靠 Node/Python 桥接；外部 Agent 的语言不受此限制。

本工具及直接/传递/构建/测试依赖源码与必要资源应固定纳入源仓库，带来源版本/提交、许可、notice 和必要修改记录，在所需 Rust/Windows SDK 就绪的干净环境离线解析构建；不依赖其他开发目录/本地缓存。工具链、Windows 组件、外部 Agent 及私人认证不是要拷入仓库的依赖，运行包也不要求装下全部开发源码。成熟后端证据、离线构建与真实协议兼容性要分别核对，不能相互替代。

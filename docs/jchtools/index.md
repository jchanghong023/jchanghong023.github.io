# JchTools 同事使用指南 {#overview}

JchTools 是 Windows 本地工具箱：把文件解压、资料整理、Markdown 处理、离线 OCR 和本机 Agent 接入放在同一窗口，但每项工具独立运行。它不是文件备份软件，也不是企业文档平台。先阅读[安装与首次使用](./getting-started)，涉及真实资料前再核对[安全边界](./contract#safety)。

::: warning 先保护原件
目录整理默认永久删除重复副本，递归解压完整成功后永久删除源包及实际分卷；不经回收站，没有软件内恢复、回滚或任务重放。首次使用请选择自行准备的副本目录，不要直接处理唯一资料。
:::

## 按工作目标选择工具 {#tools}

| 目标                                     | 使用入口                               | 最重要的区别                                   |
| ---------------------------------------- | -------------------------------------- | ---------------------------------------------- |
| 解开压缩包及内层包                       | [递归解压](./recursive-extract)        | 就地解压，成功删源；不顺带整理                 |
| 去重、归类和清理目录                     | [目录整理](./directory-organizer)      | 先只读分析，再逐项审核计划                     |
| 合并或限大小拆分已有 Markdown            | [MD 整理](./md-tools)                  | 原文件只读，不做格式转换                       |
| Office、PDF、图片及音轨转 Markdown       | [转 Markdown](./all2markdown)          | 文档与图片基础资产随包；音频资产需主动下载     |
| 一个文件一次提交并推送                   | [Git 工具](./git-tools)                | 使用系统 Git 与当前 upstream，不是通用 Git GUI |
| 框选屏幕提取布局文本、程序识图           | [截图 OCR 与 jchocr](./snap2text)      | 截图从热键或托盘触发；jchocr 是独立图片命令    |
| 用本机 HTTP 调用外部 ACP Agent           | [模型服务](./acp-model-service)        | 后端 Agent 执行工具；不是 Xberg 离线推理       |
| 维护已登录 CodeAgent 的本地 Token        | [CodeAgent](./codeagent)               | 当前用户本地凭据维护，不联网、不显示 Token     |
| 检查共同资产、下载音频依赖或管理截图后台 | [共享 Xberg 与设置](./xberg-inference) | 同一共享目录、至多一个 Xberg，不合并业务任务   |

例如，想完成一轮资料整理，应先手动运行递归解压，再手动打开目录整理。解压完成不会自动开始去重；转换也不会自动合并 Markdown。截图和文档共用推理组件，不意味着相互调用。

[覆盖表](/coverage)及本目录 `coverage.json` 记录全部 11 份来源的字节摘要、源码修订、标题映射和需求编号。来源状态为 **working-tree**：包含读取时工作树内容，不能据此推定公共发行包已包含全部行为。公开下载版本与现行需求的区别见[下载边界](./getting-started#downloads)。

所有页面中的“应当”“预期”“要求”描述现行产品合同，不是本站重新测试的结果。本次文档工作没有安装产品、调用模型、操作桌面或运行产品测试。来源中的历史成功、已接入代码、CI 成功、发布文件存在，均不能替代对应版本的实际功能验收。

## 工程与验收信息如何阅读 {#engineering}

维护者定位实现时，GUI 与注册表负责真实页面接入；文件核心负责扫描与任务合同；各工具、资产、共享推理、模型服务及 CodeAgent 按 Rust workspace crate 分离，Slint 生成代码单独编译。jchocr 是独立 package，截图托盘服务单独运行。这样的模块边界服务于缓存复用和责任隔离（P-14），不代表某项功能已验收。

发布脚本应记录准备、资产校验、编译、组装、许可、安装包及 ZIP 各步骤和总耗时（P-15），不能把整条 Cargo 耗时称为纯编译，也不能用缓存设计推算真实性能。引擎来源锁定见 XB-10，基础资产与音频可选资产界线见 XB-27，详见[交付与验证](./contract#delivery)。

同事使用时优先关注实际发布说明中的适用版本、已验证项目与未验证项目。真实桌面、真实固定模型、多显示器、后台常驻、包内资产以及媒体链路，都不能由单元测试或模拟引擎结果代替。模型服务也不承诺任意外部 Agent 都兼容。

## 与其他工具的关系 {#related}

[OMP](/omp/) 提供 Agent 核心与终端工作流，[OmpCode](/ompcode/) 提供桌面交互；JchTools 则提供独立 Windows 文件与文档工具。OMP 可通过模型服务的受限发现协议访问后端 Agent，但这不为文件整理工具增加远程自动化接口。

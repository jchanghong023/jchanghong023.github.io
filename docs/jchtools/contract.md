# 共用边界、文件安全与交付 {#contract}

本页解释所有工具共同适用的规则；每个工具的具体操作仍由各自页面说明。冲突时最高优先级 H 分区在前，其次数据安全 S 分区；示例不覆盖明文规则。需求覆盖不等于产品验证。

## 独立工具与优先级 {#priorities}

H-01、H-02 要求个人资料处理兼顾性能和流畅：不重复扫描、计算或复制，不以漏文件或错误删除换速度；扫描、哈希和解压不应阻塞 GUI，状态与取消可见。H-03 不把工具自动串联；需要全流程时用户先解压、再整理。

H-04、H-07 的解压完成只指范围内白名单归档全部完整处理：完整成功的包永久删源，无法解开的包保留隔离；已有文件不被淘汰，重名只改新文件主体、不改扩展名。外层成功、内层坏包时外层仍可删源，但整次任务不能称全部解压成功。H-05 的最终空目录清理只属于目录整理，不是解压附带动作。

H-06 固定保护 Git 树：任意目录直接含 `.git` 文件或目录（大小写无关）即视为项目，不验证标记内容；只取最外层项目。根或祖先直至卷根有该标记，解压和整理整次拒绝；边界检查失败也不开始。范围内子项目不读内容、不哈希、不清理、不改内部文件，唯一允许动作是目录整理的同卷整项目移入「Git项目集合」。不能通过操作祖先绕过保护。转 Markdown 与 MD 合并为只读扫描，有各自明确例外。

H-08 不设屏幕阅读器、辅助技术或专门键盘焦点的无障碍开发与验收要求；普通鼠标键盘易用性仍在要求内。

## 产品范围与隐私 {#scope}

P-01～P-08：JchTools 是中文 Windows 个人本地工具箱，不是企业多人协作或私人文档管理平台。导航由真实工具注册表生成，文件、文档、开发各类别没有空占位；共享设置不是另一套 GUI 产品。主题默认深色，可在关于页切换浅色/跟随系统。

安装版与便携 ZIP 并列交付，当前用户安装免管理员；截图/文档 OCR 资产随包，音频可选资产另行主动下载。除 jchocr 图片 OCR 和本机模型服务 HTTP 的特定边界外，不提供用户 CLI、MCP、历史报告或 CSV/日志导出。内部服务启动参数不是用户批处理接口。

通常文件处理离线，不上传资料、路径、正文或日志。P-03 的例外仅限：用户点击关于页明确官网地址由浏览器打开；用户启动 Git 后访问当前 upstream；用户在设置主动下载匹配音频资产；ACP 后端 Agent 为请求访问自身模型服务；jchocr 显式下载调用方指定 HTTP(S) 图片。这些例外不能互相借用。模型服务**不承诺离线推理**，Agent 可能把提示和工具读取内容发送给自己的模型供应商。

P-08 假定处理期间资料不被其他程序修改，不实现外部变化检测、二次快照或并发攻击防御。操作时关闭会改写同一目录的程序；这不替代程序本身的不覆盖和路径安全义务。

## 删除、范围与失败保护 {#safety}

::: danger 不可恢复的操作
S-02：目录整理全局文件删除默认「永久删除」，只有「保留」或「永久删除」，无回收站选项。清理规则可单独覆盖全局选择；全局保留不代表所有规则都不会删除。递归解压则没有删除方式选择，整包完整成功后永久删除实际源卷集。软件不提供备份或恢复。
:::

- **S-01**：移动、改名绝不覆盖。固定「文档」「Git项目集合」「解压失败」等容器被文件、项目或链接占用时，不挪走占用项、不偷偷换容器名；相关源项保留并显示失败。合法长路径不统一按 260 字符拒绝，实际路径/权限/名称不可用时安全失败。
- 普通文件跨卷需完整不覆盖复制、设置创建和修改时间、关闭输出成功后才删源；任一步失败保留源项。源删除失败两份保留、报告未完成，不声称原子回滚。Git 项目跨卷不复制，直接保留失败。
- **S-03、S-08**：内容去重依据整文件哈希一致，不在删除前二次逐字节比较；“最新”是 mtime，不是文件名、语义或软件发布版本。
- **S-04、S-05**：不跟随、不移动、不删除符号链接、junction、reparse point；根或访问路径经过链接边界即拒绝。不自动提权、不清只读属性；实际 Windows 系统目录及后代禁止选取，高层根则排除那棵系统树。不把限制扩大到所有用户目录或盘根。
- 默认递归、包含隐藏和系统属性、排除 glob 为空。用户关闭范围后应显示限制，排除树不统计内部，不得靠搬祖先突破；不能读的条目需有原因，不算全部成功。
- **S-06**：删除摘要是逻辑大小，不等于 NTFS 实际释放量；可靠识别同一物理文件的硬链接不重复计算或删除独立副本。
- **S-07**：无备份、事务回滚、断点恢复或任务重放；取消后已完成动作保留，新任务重新分析。只清理本次明确拥有的临时产物，不凭名字删除历史残留。

## 规则与默认值 {#rules}

R-01～R-04：解压/整理规则在各自页面，会话内有效，重启恢复默认；规则快照仅服务本次计划，不是偏好恢复或历史任务 UI。MD 和 Git 直接在功能页配置，无规则面板。共享 Xberg、截图快捷键、自启、CodeAgent 间隔等应用级配置另有持久化。

目录或规则变化使旧整理计划失效，必须重新分析。关闭递归只纳入根直接普通文件，直接子级 Git 项目可按整体规则归类；不会因创建了分类目录就把其深层旧内容重新纳入。

| 参数                         | 默认与有效范围                                               |
| ---------------------------- | ------------------------------------------------------------ |
| 递归、隐藏、系统属性         | 均开；排除 glob 空                                           |
| 解压最大层数                 | 16；整数 1～64，顶层为 1                                     |
| 单包条目上限                 | 1000000；整数 1～1000000000，不可 0 关闭                     |
| 最大展开比例                 | 10000；整数 0～1000000000，0 为关闭                          |
| 磁盘预留                     | 1 GiB；0～9223372036854775807 字节，0 不忽略写入失败         |
| 同名、副本名、不同名去重     | 开、开、关                                                   |
| 保留者与全局删除             | 最新 mtime；永久删除                                         |
| 大文件单独归类               | 关；阈值 1 GiB，范围 1～9223372036854775807 字节，等于也命中 |
| 系统附属/临时备份/零字节清理 | 开/关/关；各自可覆盖删除方式，默认跟随全局                   |
| 副本后缀、NFC 与连续空白     | 开；NFC 与空白共用一个开关                                   |
| 内容签名修正扩展名           | 关                                                           |
| 整理哈希线程                 | 6，整数 1～16；机械盘建议 1                                  |

数字为有限非负十进制；计数/线程必须整数，容量按 B/KiB/MiB/GiB/TiB 换算后为整数字节。启用项非法、溢出或越界会阻止分析/开始，不自动钳制；关闭项的附属输入不阻塞其他处理。解压不提供统一输出、去重、覆盖淘汰或逐次询问；整理不提供关闭归类、改变层级、硬链接替换、最大/最小保留者或关闭最终空目录清理。

## 名称、比较与格式修正 {#names}

附录 B 为解压与整理共享名称定义，但危险归档成员绝不能靠改名“修好后放行”。

### 扩展名与 Windows 比较 {#extensions}

普通扩展名是最后一个非空点后段；`.gitignore` 整体为主体。`.tar.gz`、`.tar.bz2`、`.tar.xz`、`.tar.zst`、`.tar.lzma`、`.tar.z` 整体保留；分卷编号、`.partN.rar`、`.rNN`、`.zNN` 也不拆散。项目目录含点仍整体为主体。Windows 同名使用与语言无关的 ordinal ignore-case；平局先按统一 `/` 的原相对路径忽略大小写比较，再以原始 UTF-16 单元序列决胜。长度同样按 UTF-16 单元计算，不是中文字符数。

### 副本标记和合法化 {#normalization}

只识别主体末尾连续的 `(N)`、忽略大小写的 `- Copy`、`副本`，不处理主体中间字串。去重名称键剥全部尾标记；输出名把数字转 `_N` 并去前导零，其他标记移除：`报告 (1) (02).pdf` → `报告_1_2.pdf`，`report - Copy (1).tar.gz` → `report_1.tar.gz`；已有 `_1` 不再剥除。

开启时先 NFC、把 Unicode 连续空白压为一个 ASCII 空格并去主体首尾空白，再清理副本标记。派生主体禁用字符/控制字符替换 `_`，末尾 ASCII 点和空格移除，空主体、`.`、`..` 使用 `_`，设备保留名加前导 `_` 后重验；扩展名不能合法保留则失败。加入来源段后也要达到稳定名称再判占用；不改源目录名。项目目录不执行普通文件副本清理。

### 可选内容签名修正 {#signatures}

仅分析阶段、开关明确开启时判型，无法可靠确认就不改。要求可识别 PNG/JPEG/GIF/BMP/TIFF/WebP/PDF/FLAC/WAV/ZIP/7z/RAR，以及 ZIP 内类型可确认的 DOCX/XLSX/PPTX、DOCM/XLSM/PPTM、ODT/ODS/ODP/EPUB。合法 jpg/jpeg、tif/tiff 不强制统一；无法确认内部类型的 Office/ODF/EPUB 等不能降级为 `.zip`。不凭几个魔数猜测，不更改 Git 项目内部文件。

## 排除 glob 怎么写 {#glob}

附录 C：分号分隔、去段首尾空白、空段忽略，任意一个匹配即排除。相对根路径统一 `/`，模式中的反斜杠也是分隔符。匹配整个相对路径，忽略大小写；`*` 可跨 `/`，`**` 无额外语义，`?` 恰好一个非 `/` Unicode 字符。不支持字符类、正则、否定、引号或转义。

| 写法            | 含义                                               |
| --------------- | -------------------------------------------------- |
| `*.tmp`         | 任意深度以 .tmp 结尾的文件或目录；命中目录整树排除 |
| `cache`         | 仅根直接子项 cache                                 |
| `*/cache`       | 深层 cache，不包括根直接子项                       |
| `cache;*/cache` | 根与深层 cache                                     |
| `a/?.txt`       | 匹配 a/x.txt，不匹配 a/xy.txt 或 a/b/x.txt         |

绝对路径、盘符或独立 `..` 段为无效模式，会阻止开始。隐藏和系统属性是两个独立包含开关，任一关闭且命中该属性就排除；Git/链接/系统目录/隔离容器优先，glob 不能重新纳入保护树。

## 窗口、进度与日志 {#interface}

U-01～U-13：主窗口居中、默认 1120×720、最小 960×620，标题栏可拖动、双击最大化；面板用 Tab、规则分区用 Pill。布局缩放不裁切按钮，长路径/状态只在自身区域省略，诊断长内容受限滚动。目录对话框从已输入位置开始；切换工具回该工具默认面板，不串用不存在页签。

总量未知的扫描、哈希、解压用活动提示与实际计数/速度，不伪造百分比；总量已知才显示进度。蓝色提示与红色错误分别可关闭，主动取消不是错误。运行日志最新在上、最近 300 条，可窗口内放大、复制，Esc 还原；放大不停止任务、不盖过关闭确认。解压的本次失败分页列表另行完整保存至下一次解压或退出，301 个失败也能查到最后一个，不是跨运行历史库。

主窗口在途文件任务关窗要确认安全停止；仅截图或模型服务运行则关窗不停止后台。软件渲染入口见[安装指南](./getting-started#install)。后台 Git/扫描/MD 不得让 UI 假死，错误要含文件或 Git 阶段等必要上下文。U-04 不增加无障碍验收范围。

## 下载与本地诊断 {#network-logs}

P-09：应用自身音频资产下载使用 Windows 手动代理及例外表，PAC/WPAD 不支持；代理传输失败直连重试一次。现行下载器从首个 HTTPS 请求起跳过服务端证书信任链、域名和有效期校验，重定向沿用，**不保证服务器身份**；仍有 TLS 加密、握手签名、固定来源与摘要检查，不改变系统证书。Git 完全继承自己的配置；jchocr 不套用音频下载器的跳过证书策略。

P-10：关键生命周期、任务、IPC、失败及已有重试写本地诊断 `.log`，一事件一行、毫秒时区时间、PID/线程/组件/稳定事件名与请求关联。每次真实进程启动独占文件，PID 复用也不续写；Xberg 性能数据同样按引擎启动隔离。单文件最多 1 MiB，每个落点最多 10 个自有诊断文件、最长保留 14 天；不清理归属不明文件。默认关键 INFO、可恢复 WARN、最终失败 ERROR，DEBUG 仅额外细节。

不记密码、Token、认证头、Cookie、配置全量、正文、截图、OCR、提示或无限 stdout/stderr；地址和错误仅有界去敏。主日志失败尝试用户级备用目录，仍失败 stderr 去敏报告，不弹窗、不终止业务、不递归记录。诊断日志与 UI 300 条日志不同，均不授权上传或提供导出功能。

## 交付与验收不能混为一谈 {#delivery}

E-01～E-05：7-Zip 从官方固定版本 release 获取并校验，记录架构、来源、上游包与运行文件 SHA-256。运行按 EXE 同目录 `resources/7zip` → 已释放内嵌副本 → 从 EXE 新释放的顺序查找，全部必需文件校验后才执行。无效候选不执行、不覆盖，必要时释放到新的自有位置；全不可用即报错停止，不提供任意引擎路径参数。

发布两种包保留许可证、NOTICE、7-Zip 上游源码与来源清单，禁止独立 7-Zip 引擎可执行文件泄漏；Xberg 随包不受这条“独立 7-Zip”限制。构建机缺 7-Zip 时可编译不内嵌，不等于成品可以解压。两种包都应有软件渲染入口与完整 Xberg 基础资产；未执行阶段必须标 NOT RUN。

P-11～P-13 要求长期维护 GUI 自动化、需求到测试映射及从真实入口断言结果，最终目标无人值守，不依赖人工目视补齐。Windows 本地功能验收与 CI 编译/打包/发布分开；编译、单测、模拟、点击无崩溃或 Release 存在都不能证明真实模型、后台、桌面与交付完整。P-14 的独立 crate 缓存和 P-15 的逐步骤计时是工程要求，不是已测性能结论。本站未执行这些产品验收。

## 常见边界应得到什么结果 {#boundary-examples}

附录 E 的可观察期望包括：分类固定一级、项目平铺；名称规范化造成冲突也不能覆盖，已有不变目标优先；合法不冲突长名不强制截短。全局保留且清理跟随全局时没有文件删除，但归类和空目录清理仍进行；某项显式永久删除只影响该清理项。

包内有普通与危险成员时整包拒绝，不提交“安全部分”；缺号分卷是一组失败，不逐卷解压；完整 zip 与数字尾卷集共存是两个包；隔离目录中的包不自动重试。MD 代码围栏里的井号不改、六级标题封顶、输出文件不回读为输入；1 MB 拆分实际不超过 1048576 字节，分片二进制拼接还原原文。Git non-fast-forward 走 fetch + merge，不 rebase，冲突保留；已有 staged 按路径单独提交，push 退避可停止，已成功文件不重复提交。各例的操作说明见对应工具页。

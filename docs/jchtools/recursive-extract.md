# 递归解压：就地解包与源包清理 {#recursive-extract}

递归解压只处理明确白名单中的归档，不去重、不归类、不清理普通资料、不自动打开目录整理。与只读浏览压缩包不同，它在每个包完整成功后**永久删除原包和实际分卷**。请先用资料副本熟悉流程。

## 第一次操作 {#workflow}

1. 选择待处理副本目录，确保所选根及祖先不是 Git 项目，不经过链接，也不是 Windows 系统目录。
2. 在「处理规则」确认递归、包含隐藏/系统属性和排除 glob。默认递归；防护默认 16 层、100 万条目、展开比例 10000、磁盘预留 1 GiB。
3. 点击「开始解压」。扫描结束的唯一确认框说明初始包数、就地输出、成功删源、已有文件保留、重名自动编号及失败隔离；同意后连续执行，没有逐项计划审核。
4. 观察实际处理数、新发现的嵌套包与失败列表。零个可处理包不启动空任务；确认数不预估尚未解出的嵌套包，不突破 Git/隔离/用户排除树统计。
5. 完成后检查“成功、失败、取消、范围限制及源包清理失败”分别是什么，不能仅凭有文件解出就认为全部成功。

X-01～X-04：每包解到自己所在位置，不提供统一输出。已有同名文件不动，新文件主体加最小未占用编号，如 `资料 (1).txt`、`资料 (1).tar.gz`，扩展名大小写及复合后缀保持。即使内容一样也正常落盘，不做哈希淘汰。普通目录可合入，内部逐项不覆盖；目录名被文件占用时给新目录整体改名。不能合入 Git、隔离或链接保护树。

## 哪些格式会处理 {#formats}

白名单（大小写无关）：`.zip`、`.7z`、`.rar`、`.tar`、`.gz`、`.bz2`、`.xz`、`.zst`、`.lzma`、`.z`、`.tgz`、`.tbz2`、`.txz`、`.tzst`。压缩流允许 `.tar` 复合后缀，例如 `.tar.gz`，整体是一包/一层，不留下中间 tar。单流有成员名用成员名，无成员名按去掉压缩后缀命名，如 `资料.txt.gz` → `资料.txt`。

X-09 的白名单外文件完全不碰，即使引擎能打开也不计包、不移动、不改名、不隔离：CAB；MSI/MSIX/APPX 及 bundle；ISO/IMG/WIM/ESD/VHD/VHDX；JAR/WAR/EAR/APK/AAB/WHL/NUPKG/VSIX/CRX/XPI/IPA/PKG/DMG；DOCX/XLSX/PPTX 及宏变体、ODT/ODS/ODP/EPUB；LZ4/BR/LZ；EXE/COM/自解压程序。白名单外分卷如 `.iso.001`、`.docx.001` 和无法指认归档类型的 `data.001` 也不处理。它们可在目录整理中作为普通文件分类，但不会被“补解压”。

## 分卷是一组，不是多个文件任务 {#volumes}

X-10 先按同目录、同主干、同命名族归组，再判断完整性。缺首卷或断号仍是一组失败包，只计一次，不把尾卷独立解码。

| 命名族                                                  | 入口及边界                                                                        |
| ------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `data.7z.001`、`data.zip.001`、`data.tar.gz.001`        | 完整白名单后缀再加规范数字；从 001 开始，至少三位，999 后自然到 1000，不限 999 卷 |
| `data.part1.rar`、`data.part01.rar`、`data.part001.rar` | 各最小补零宽度需一致，入口为该模式编号 1；混用宽度或重复号判命名歧义，不猜        |
| `data.rar` + `.r00`～`.r99`                             | 主 `.rar` 为入口；仅尾卷也归组并报缺主包                                          |
| `data.zip` + `.z01`～`.z99`                             | 主 `.zip` 为入口；仅尾卷同样失败                                                  |

数字尾卷只接受 ASCII 规范编号：`.000` 使整组非法；不足三位、多余前导零、非 ASCII 数字和备份尾缀不属于正常族。编号连续还需引擎整包校验通过，不证明尾卷齐全。`data.zip` 与 `data.zip.001`～`003` 共存是独立 zip 和尾卷集两个包，不能相互删卷；part rar 与老式 rar 也独立。

成功删除/失败隔离只作用于精确识别的实际存在卷，不吸入相似主干说明、备份或其他格式。隔离重名时整组统一改主干，如 `data (1).7z.001`、`data (1).7z.002`，编号与原后缀不变，选择整组都空闲的最小序号；歧义组也不能重命名成看似完整的族。

## 何时删源、何时保留 {#results}

X-05：整包解码、校验和所有成员正式落盘均成功后才开始永久删源，包括成功空包；每层独立判断。外包完整落盘后，内包损坏不撤销外包成功，外包可删，内包应保留隔离。任一成员未落盘则本包不能删源。取消前检查删除边界；源删除失败单独显示“清理阶段失败”，不冒充坏包、也不假报全部成功，多卷删除不承诺事务回滚。

X-06：损坏、加密、引擎不支持、分卷不全、防护超限或危险成员等无法完整解开者，不删除，整组不覆盖移入根下「解压失败」。固定容器被占用或不能创建时源包原地保留，显示隔离失败；部分卷移动失败需分别列出已移动/未移动位置，不能说整组已隔离。其他不依赖此失败的包可继续。

**空间不足或用户取消**不是坏包：当前源包原地保留并停止整次任务。普通结果已落盘的不回滚。失败列表显示原路径、原因和隔离位置，可分页查询全部本次失败，超过 300 项不截断；GUI 运行日志仍只显示最近 300 条。切换工具不清空本次失败列表，下一次解压或退出才结束保留。

X-07：同次任务不重复入队；新任务不靠历史哈希自动跳过。任何名为「解压失败」的目录整树固定排除，包括手动放入的正常包；根本身叫此名则拒绝开始。重试需先由用户把待重试包移到隔离容器外，再启动新任务，不能把隔离说成已解压。整理中的保留与幂等另见 C-09、C-10。

## 防护、磁盘空间与取消 {#guards}

X-08：顶层深度 1，等于上限允许，超过才隔离。条目数包含文件、目录和重复路径；展开比例按累计逻辑输出字节/实际输入卷集总字节，零输入非零输出为无穷，均零为 0。没有额外固定 TB 单包上限，但仍受这些保护、空间与文件系统能力限制；多 TB 可处理是需求，不是性能实测承诺。

解压前和运行中检查空间，默认保留 1 GiB；需容纳当前整包的临时完整输出，不是零额外空间。未知大小也不能只开始前检查一次。空间不足停整次，不批量隔离正常包。

路径穿越、绝对/盘符相对/UNC/设备路径、ADS、软/硬链接成员、加密、非法或无法解码名称任一出现使整包失败，不能仅跳过危险成员后宣称成功。先解入同卷随机所有权临时区，整包检查通过再不覆盖合入；预检/解码失败不合入任何临时内容，合入阶段失败保留已落盘与源包并披露部分完成。

取消在文件安全边界生效，不开始后续合入或删源；不回滚完成结果。临时区只按本次所有权清理，不动用户目录，不按名称回收旧工作区；崩溃、强杀或清理失败不能当成功。正常清理失败会提示位置与原因，历史残留由用户另行决定处置。

关闭递归时只继续处理落在根直接层级的新嵌套包，子目录中的包不继续解，并显示范围限制。引擎不可用会明确停止，不能静默跳包；[7-Zip 的来源和运行校验](./contract#delivery)与普通 Xberg 替换规则不同。

# 安装与首次使用 {#getting-started}

最终用户不需要 Rust、Windows SDK、Python、Node.js 或单独安装 7-Zip。请选择项目的 Windows x64 成品包；OCR 和转换场景另要求 Windows 11 x64、AVX2 CPU，使用 CPU 推理，不要求 GPU。这个场景限制不应被扩大为其他文件工具也必须具备 AVX2。

## 从正确仓库下载 {#downloads}

下载入口是 [jchanghong023/JchTools Releases](https://github.com/jchanghong023/JchTools/releases)，不是第三方镜像。2026-10-17 查询到的最新公开发布为 [20261015-2004](https://github.com/jchanghong023/JchTools/releases/tag/20261015-2004)，列有：

- `JchTools-Setup-x64.exe`：当前用户安装包。
- `JchTools-Windows-x64-20261015-202211.zip`：便携包。
- `SHA256SUMS.txt`：该次发布的文件校验和。

**可下载不等于符合全部现行需求。** 本指南来源工作树还包含 2026-10-17 的 Xberg 与 OCR 规则更新，时间晚于上述公开包；本站只核对了发布元数据，没有下载、解包或执行这些资产。遇到界面或模型行为差异，先比较下载版本与该发布的说明，不把后续源码行为套用成旧包的已验证能力。

下载后可在 PowerShell 对实际文件名运行以下只读校验，并将结果与同一发布的 `SHA256SUMS.txt` 对照：

```powershell
Get-FileHash .\JchTools-Setup-x64.exe -Algorithm SHA256
```

不要混用不同发布的安装包、ZIP 与校验文件。校验和用于完整性核对，不构成对功能或发布者身份的额外保证。

## 安装版与便携版 {#install}

**安装版**：运行下载的安装程序，按向导安装到当前用户目录。按产品交付要求不需要管理员权限或 UAC，默认创建桌面快捷方式、开始菜单入口及系统卸载项。升级或卸载会先请求 CodeAgent 自有后台自然退出；维护失败应阻止替换或卸载，而不是强杀无关进程。不要手动删除凭据来解决升级问题。

**便携版**：把整个 ZIP 解压到自己可写的专用目录，保留目录结构，再运行其中的 `JchTools.exe`。不要只复制主 EXE：`jchocr.exe`、截图 worker、`xberg/`、清单、运行库、字体与许可构成共同交付。便携不等于无状态，应用级设置仍会保存。

正常入口显示图形界面；若图形驱动异常，可运行同目录 `launch-software.cmd` 请求软件渲染。这个脚本仍启动同一 GUI，不接受文件删除、目录处理或批处理参数。软件渲染效果也应以实际 Windows 环境为准。

不必另装 7-Zip：完整引擎由程序按发布清单校验、释放后使用。杀毒软件可能对“释放并执行引擎”敏感，不能据此让用户关闭系统防护；引擎不可用时查看明确错误与发布修复说明，不随意替换任意同名可执行文件。

## 第一次打开窗口 {#first-open}

1. 确认左侧八个工具及独立「设置」「关于」入口。主题默认深色，可在「关于」中选择浅色或跟随系统。
2. GUI 应先可交互，再后台发现随包共享运行目录，连接或启动截图与 Xberg 后台；模型加载可能需要等待，未就绪应显示具体原因。
3. 打开「设置」查看文档/图片、截图、FFmpeg 与音频模型各自状态。截图和文档基础资产按现行要求随包，不需要下载、手填目录或旧缓存；缺损应修复安装或重新解包。
4. 登录自启默认关闭；按需显式开启，不要把“关窗后常驻”误认为“默认开机启动”。

## 选一个低风险起步任务 {#first-task}

| 第一次做什么                        | 操作与应观察结果                                                                                                     |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 合并几份非敏感 Markdown 副本        | 打开 MD 整理，选目录和一个新输出文件；确认标题下移、代码块不变，原文件仍保留                                         |
| 转一份自备非敏感 PDF 或 Office 文件 | 把它放入独立输入目录，另选输出目录；检查生成的 `文件名_原扩展名.md` 及相对图片引用，源文件不变                       |
| 框选一小段可公开文字                | 等截图就绪后按 Ctrl+Alt+O，拖选后查看布局文本；Esc 或右键取消，结果窗可复制                                          |
| 预览目录整理                        | 只选资料副本，先把全局文件删除方式改为「保留」，检查各清理项是否单独覆盖永久删除，再开始分析；未确认执行前不应改文件 |

::: warning “保留”不是完全只读
目录整理即使不删除文件，确认执行后仍会归类、改名，并固定清理范围内实际空目录。只有“开始分析”是只读阶段。递归解压没有保留源包开关，整包成功后会永久删源；不要把它作为无损查看压缩包的工具。
:::

后续进入各工具页面阅读[完整首次流程](./index#tools)。Git 另需已安装且 PATH 可用的 Git for Windows，并提前配置身份、认证、分支及 upstream；外部 ACP Agent 则由用户自行安装和认证，均不随 JchTools 提供。

## 音频可选资产与网络提示 {#audio-assets}

现行默认包不含 FFmpeg、SenseVoice INT8、Silero VAD 音频资产；这不影响截图、文档/图片转换或 jchocr。需要 MP4/M4A 音轨转录时，在「设置」明确点击下载，等待 FFmpeg 及配套 DLL/许可、音频模型全部就绪，再开始转换。处理文件时不会自动补下载。

下载匹配包内引擎清单，不为追新替换已有有效引擎和共享 DLL。网络使用 Windows 当前用户手动代理；PAC/WPAD 不支持，经代理传输失败后只直连重试一次。现行策略从首次 HTTPS 请求起跳过服务端证书信任链、域名和有效期校验：仍有 TLS 加密及文件摘要校验，但**不保证服务器身份**。403 访问限制或 407 代理认证失败不能靠跳过证书解决。Git 与 jchocr 不能据此继承该下载器的证书策略。

媒体真实限制与大文件缺口见[转录限制](./all2markdown#media-limits)，不要先拿大视频试探可用性。

## 关窗、退出与升级 {#exit}

- 解压、整理、MD、Git 或转换任务进行中，关窗先确认“停止任务并关闭”，按工具自己的安全边界停止；转换尽快取消当前文件。没有自动回滚。
- 只关闭 GUI，不会退出截图服务、热键、托盘及共享模型。完全退出这组后台用托盘「退出后台服务」，等待在途任务安全停止。
- 模型服务从自己的页面独立退出，不在截图托盘退出范围内。CodeAgent 后台也独立，普通关窗不会停止凭据维护。
- 升级遇共享协议不匹配时，先通过旧版托盘退出截图/Xberg 后台，再打开新版，不用杀进程制造第二个引擎。旧有效 Xberg 来源在安全迁移完成前保留，不能自行删除旧目录。

## 故障时先看哪里 {#troubleshooting}

工具页区分配置错误、文件失败、取消、超时与部分完成；运行日志可“放大”后滚动、选择、复制，Esc 还原，最近 300 条、最新在上，不提供报告导出。解压另有不受 300 条限制的本次失败分页列表。应用本地诊断日志不应包含正文、截图或 Token；共享日志时仍应人工核对必要的隐私范围。

当前指南不承诺网络盘、多个 TB 性能、各种 DPI 或任意 ACP Agent 已验收。来源 README 明确保留这些验证缺口；需要对应发布的真实结果，而不是要求使用者替开发者证明“应该可用”。

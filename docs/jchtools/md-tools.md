# MD 整理：合并与无损拆分 {#md-tools}

MD 整理只处理已有 Markdown，不是[转 Markdown](./all2markdown)。M-01 的范围只有“合并 MD”“拆分 MD”，不提供格式化、目录生成、图片整理、链接检查或 Front Matter 管理。源文件不改、不删、不移动；新输出位置由用户指定。

## 首次合并 {#merge}

1. 打开「MD 整理 → 合并 MD」，选择含 Markdown 副本的目录。
2. 选择是否递归；不递归只读根直接的 `.md`，递归读全部子目录匹配文件，后缀大小写无关。
3. 指定一个新 `.md` 输出文件，开始处理；目标已存在先模态确认，未经明确覆盖授权不得破坏旧文件。最好让输出在输入目录外便于检查；即使位于扫描目录内，本次输出也不会回读为输入。
4. 核对文件顺序、每份文件名标题、正文标题与代码围栏。源文件仍原样保留。

M-02～M-04：只读扫描不排除 Git 项目和隐藏/系统属性文件，但不跟随符号链接、junction、reparse point。排序按创建时间从早到晚，创建时间不可得用修改时间；平局用相对路径自然排序，数字段按数值、非数字按 Unicode 码点，所以 `2.md` 在 `10.md` 前。

每份输入前新增 `# 文件名.md` 一级标题，再放下移标题的正文，文件间保留必要空行，不额外加入分割说明或元数据。流式逐文件逐行处理，不应把全部目录装入内存或阻塞窗口。

## 标题转换与代码保护 {#headings}

M-05、M-06：ATX 一级到五级下移一级，原六级保持六级，绝不生成七级；只把行首至多三个空格、井号后接空格或行尾的有效标题当标题。Setext 的 `=` 一级转 ATX 二级，`-` 二级转 ATX 三级，下划线行不再输出，需紧邻非空正文且不在代码内。

反引号与波浪线围栏都保护，语言标签不影响；结束需匹配开始字符及足够长度。围栏中的 `# shell comment`、看似 Setext 下划线等均保持原样。四空格缩进行既不当围栏也不当标题。原图片链接不会被重写成本工具的图片管理能力。

## 按硬大小拆分 {#split}

M-08～M-11：选一个 `.md` 文件，设单片最大 KB/MB，选择输出目录，再开始。固定 1 KB = 1024 字节、1 MB = 1048576 字节；必须为正数且换算为整数字节，非法值会阻止开始，不自动截断或钳制。

大小是**实际 UTF-8 字节硬上限**，不是字符数，不为完整章节、段落、代码块或表格放宽。可以在任意安全 UTF-8 字符边界切分，因此单片不保证 Markdown 结构完整。中文、日文、Emoji 不能从中间切坏；限制小于最大单字符字节数、无法同时满足两项要求时应报错并不产生输出。

输出如 `document_001.md`、`document_002.md`；编号宽度按实际总数统一，超过 999 扩宽，按文件名排序仍正确。写入前检测所有目标冲突，已有同名分片先模态确认，不静默覆盖；大文件使用分块读写。

把所有分片**按编号顺序直接二进制拼接**应完全还原原始字节：不丢、不重、不改顺序，不插标题、分隔线、序号或注释。不要用编辑器自动补换行后保存再拿它当无损证明。

## 取消、错误与完成判断 {#results}

M-07、U-12 要求合并/拆分在后台执行，日志与停止可用；主动取消不是错误。文件不可读、大小非法、输出冲突或写失败应显示具体路径/阶段，不能只写“失败”。源文件始终只读；输出覆盖必须是本次明确确认，不能套用解压/目录整理的删除授权。

本页给出需求与可观察检查点，不代表已运行真实 GUI 验收；既有 UT、合成数据或点击成功也不能替代合并实际正文和拆分字节还原结果。

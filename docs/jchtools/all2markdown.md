# 转 Markdown：文档、图片与音轨 {#all2markdown}

这是独立“文档”工具，把原文件只读转换为可本地阅读/检索的 Markdown，不自动合并、整理或删除源文件。不是打开旧项目窗口，也不依赖旧 Python 环境或历史缓存；具体资产与后台见[共享 Xberg](./xberg-inference)。

## 安装条件与交付范围 {#setup}

T-01～T-06：本场景要求 Windows 11 x64、AVX2 CPU，纯 CPU 推理，不需 GPU；条件或必需组件不满足就显示原因、禁止转换，不影响其他工具。所有用户操作在 JchTools 页面，旧脚本/独立 GUI/命令行不是产品入口。

安装包和便携 ZIP 应随附共享 Xberg、文档 tiny 与截图独立模型/字典、DLL/原生运行库、字体及许可，自动发现同一个目录，不让用户手填 Xberg 路径。FFmpeg、必要 DLL/许可、SenseVoice INT8、Silero VAD 与配套数据属于**音频转写可选资产**，默认不随包（也不压进主 EXE），仅在设置页明确操作后下载；sherpa-onnx、共享 ONNX Runtime 等其他既定依赖仍随主包。

没有音频资产仍应启动共享 worker、截图服务，完成文档/图片 OCR 与 jchocr。基础文件缺损指引修复安装/重装/重新解包，不让用户通过音频下载“修复截图”。运行按场景检查成员存在和协议能力，Xberg 成员不做运行时摘要准入；构建/主动下载仍核对来源、精确版本、大小和 SHA-256，自有后台/字体仍有自身运行校验。

## 第一次转换与输出策略 {#input-output}

1. 把自备非敏感文件副本放入专用输入目录，另选不同的输出目录。
2. 进入“转 Markdown”，选择输入、输出以及类型多选（PDF、Office、图片、视频音频、其他文档）；默认全选，全部不选不启动。
3. 检查文档/图片就绪。若转 MP4/M4A，先在设置下载完整音频资产再回页面，不会处理时静默补齐。
4. 按需选择保留层级（默认）或平铺，确认单文件超时为合适正整数秒，点击开始。
5. 检查成功、失败、已有结果跳过、同名跳过及部分提取警告，并用本地 Markdown 阅读器看图片与正文。

T-07～T-12：递归扫描匹配普通文件，文档/图片格式以实际 Xberg 能力清单为准，PDF、DOCX、PPTX、XLSX 必需，MP4/M4A 是固定媒体链路。不是宣传“100 多格式”就保证任意格式；Office 外层 ZIP 不能只输出归档清单代替正文。

源文件任何成功/失败/取消都不改写、不移动、不改名、不删除。只读扫描包含 Git 项目与隐藏/系统属性，不跟随链接、junction、reparse point。输入输出相同拒绝开始；输出在输入子树时整棵输出子树排除，避免转换自己。

每个顶层输入至多一份 UTF-8 Markdown，如 `a.DOCX` → `a_docx.md`、`a.PDF` → `a_pdf.md`，嵌入对象归宿主，不额外输出子文档结果。默认保留相对层级；平铺同名只处理稳定路径排序最前一份，其余记“同名跳过”，不改名多份、不内容去重。排序按目录段/文件名 Windows 忽略大小写序数，同键以原 UTF-16 序列决胜。

**已有最终 Markdown 直接跳过**，内容和 mtime 不变，没有覆盖确认开关。想重新生成时，由用户先另选空输出目录；不要让用户删唯一旧结果当作恢复步骤。不写永久进度状态，也不恢复旧任务。

## 正文、图片与部分提取 {#documents}

T-13～T-18：解析、OCR、Layout/Table 与嵌入递归由 Xberg 负责，文档场景 CPU、中文、paddle-ocr、PP-OCRv6 tiny，与截图 medium/small 分离。文档请求只传路径，模式与模型由引擎启动配置确定；Layout/Table 以实际编译能力为准，不能宣称未编入的能力。

常规模式保留原生文字、表格、可见字段、中文 OCR 和可解析嵌入内容；保留原图在结果旁同名 `_media` 目录（名称空白转下划线），正文用相对图片路径，不塞 Base64。重复引用保留各处位置，图片 description/title/alt 不冒充 OCR。PPTX 字段、DOCX 各关联部件、XLSX drawing 均需正确关联，不能按 ZIP/relationship 迭代顺序猜图片归属。

单图或嵌入对象失败不阻塞其余可提取内容，但必须标“部分内容未提取”和原因，分别区分资源缺失、格式未知、解码/光栅化失败、OCR 失败、无文字、无法关联。OLE 本体失败与预览 OCR 成功是不同结果。递归超限披露范围，不能把未提取部分算完整成功。

引擎负责嵌入合入、重复追加消除、深度/Visio/正文规范化；宿主有效重复正文、代码围栏、行内代码、缩进、表格行列不能被二次清理。JchTools 只改媒体目录前缀与安全落盘，不另分节或用 children 补正文；归档清单、文件名或 OCR 父子词重复不能冒充文档内容。

自动分流阈值为 **500 页/幻灯片**：PDF、Word、PowerPoint 超过进入快速模式，关闭高开销 Layout、图片 OCR 且不提取图片，必须显示 `auto_mode` 降级警告。XLSX 等无页数或探测失败回常规，不因此跳文件；快速模式的结果不能称“全部图片已识别”。

## MP4/M4A 音轨转录 {#media}

T-19、T-20：先主动下载可选资产，再经同一 Xberg 做本地解码 → Silero VAD → SenseVoice INT8，固定中文与 ITN。只取第一条音轨，重采样为 16 kHz 单声道有符号 16 位 PCM，再按原比例变 f32 供 VAD；尾部样本、片段时序不能丢。没有云端或自动语言后端切换，不新增录音采集、会议功能或视频画面理解。

结果含文件名、音频时长、语音片段数、逐段起止时间和文本。无音轨写“无音频轨道”，有音轨无语音写“未检测到语音”；解码失败是真失败，不留无解释空文件或半成品。固定术语只字面替换片段正文，不润色未知文本。

### 当前媒体真实限制 {#media-limits}

来源 README 明确记载：当前启动配置继承 **512 MiB 输入文件大小、30 分钟解码音频时长**上限，旧范围尚未恢复。30 分钟按音频样本，不等于所有视频容器的画面时长，也不同于默认 6 小时的处理墙钟超时。

虽然上层传媒体路径，当前上游 worker 仍先整文件读入内存，字节 API 又暂存媒体副本后才解码，**不应称为端到端流式/纯内存媒体链路已实现**。现行需求要求的音频数据与正文隐私边界仍保留，不能把此实现缺口解释成豁免；大文件/无落盘行为未因此验收。安全恢复依赖上游公开可取消 path API、worker 改用并发布，再接入验证；不能只去掉两个限制声称修复。不要通过配置绕限尝试大视频，以免内存耗尽影响截图。

## 停止、超时与文件结果 {#tasks}

T-21～T-26、T-29：转换离线，不访问远程转换服务、不上传正文/路径/日志；顶层输入严格一次一个，内部可用 CPU 线程，与截图跨场景并用不互斥。任务显示当前文件、成功/失败/跳过数和耗时，未知总量不编百分比。

点击停止立即接纳停止请求，尽快取消**当前文件**而非等整文件自然结束，不再开始下一份；不可中断原生调用在返回后的检查点取消，不假称瞬时结束。不杀共享 Xberg、不影响截图。当前未完整 Markdown、图片和临时产物只清本次拥有内容，前面已成功结果不回滚。关窗确认后同样处理。

默认单文件超时 21600 秒（6 小时），仅正整秒，非法不开始；超时结束当前处理、记失败，继续批次或响应已请求停止。单文件失败通常其余继续，最终要区分部分失败、配置/预检/引擎启动/未知异常及取消。最终 Markdown 仅完整成功提交，不覆盖旧结果；写失败不留下可误认成功的截断文件。

私人输入只授权本地只读转换，不能把裁剪/匿名化/重打包的内部文档当公共夹具，连可反查哈希、文件名与元数据也不发布。开发验证使用从零合成无业务内容。

## Rust、原生组件与旧工具关系 {#architecture}

T-27、T-28、T-30 及附录 D：页面/扫描/下载/任务/落盘是 Rust 与 Slint，文档 OCR/Layout 与媒体由共享 Xberg 承接；允许复用 ONNX Runtime、sherpa-onnx、FFmpeg 等原生库，不承诺依赖全由 Rust 编写。产品不安装/启动 Python、pip、venv 或旧 GUI/脚本，也不通过纯 Rust 口号减格式/换模型。

旧独立 all2markdown 项目可以不存在，升级只按 XB-21 读取旧有效配置并安全迁移匹配音频资产，不删除用户旧目录或其他项目。转换专属扫描、平台与模型不传播给原工具；全局 H-03、P-03、P-05/P-06、E-04、R-01/U-11 的独立入口、联网和规则边界仍有效，停止及 GUI 交互遵守 U-09～U-13。需要已有 Markdown 合并/拆分仍去 MD 整理。

## 验收覆盖与未验证项 {#acceptance}

附录 A 默认常用格式是 DOC/DOCX、XLS/XLSX、PPT/PPTX、PDF、MP4；独立特殊图片、其他 Office 变体、M4A、坏媒体/无音轨等扩展检查保留为可选，未跑不能计通过，也不假作必验已覆盖。

内容验收需关注：PPTX 多图/重复引用/字段/EMF/WMF/SVG 与 OLE、DOCX 正文及页眉页脚脚注尾注图片、XLSX drawing 对应、PDF 原生/扫描/重复图/软蒙版/大页数、常规图片 OCR 与快速降级、旧 Office 真实正文、逐顶层结果与原件保护。默认 DOCX/PPTX/XLSX 不等于任意变体已验证，SVG 外部资源禁用，失败阶段可分辨。

还需真实 GUI 的选择/开始/停止/关窗、同名与已有输出跳过、部分结果，以及两种实际分发在无旧项目/Python/缓存/SQLite/音频资产下自动发现、离线基础可用；再主动下载音频并验证真实转录与取消。包内引擎验收不能用另下最新版替代；资产/设置/共享进程与旧工具保留同样必要。不新增独立断网测试不等于放弃离线要求。本站未运行这些产品用例，当前媒体缺口也未被网站建设修复。

# 研发工具简明指南站需求

## 目标与范围

网站发布于 https://jchanghong023.github.io/ ，仓库为 jchanghong023/jchanghong023.github.io。面向同事快速使用工具，不是作品集、需求镜像或研发验收资料库。

**读者是使用工具的同事，不是开发者或 Agent。** 只写“有什么用、按哪里、输入什么、完成后做什么”，用日常中文和短步骤；不要求读者理解内部实现、配置结构或工具协议。必要风险用一两句话讲清，技术细节留源仓库。这是后续所有网页的默认写作标准。

使用 VitePress 默认主题，保留中文导航、搜索、明暗主题、代码复制，不另造主题，不添加统计追踪或外部字体。

## 内容与页面

首页为全屏雪林赤狐场景，仅显示 `omp` 和「知识库」两个白色文字入口，分别链接到 `/omp/` 与 `/rust-knowledge-server/`。桌面入口在左、赤狐在右；手机端赤狐位于上方，入口底部并排。赤狐呼吸和抖耳时四爪贴地，鼠标靠近或手机轻点时先转耳再抬头。鼠标经过或键盘聚焦任一文字入口时，赤狐也会短暂转耳、抬头，再恢复原姿态。细雪缓落，系统开启减少动态效果时场景静止。其余项目仍可从文档导航访问。

所有内容页共用顶部站点导航，同一栏提供搜索、外观和源码入口。正文加宽，OpenSpec 的跨页文章链接集中在右侧。手机端从顶部展开站点菜单，OpenSpec 文章列表可在正文上方靠右展开。导航和文章链接使用 `scripts/site-data.mjs` 的页面清单。

浅色文档背景使用 `#FAFAF8`，代码块与表头用浅底区分。行内代码使用中性色，正文链接保留强调色及下划线。窄屏命令表格在表格内横向滚动，单条命令保持完整。

| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

旧 OMP 独立专题页和知识库站内改写稿退出导航、搜索和构建产物。

## 来源与公开边界

- OMP 与 Rust Knowledge Server 保留指定源文档正文及章节顺序，仅补站内标题锚点、调整 Markdown 格式，并将跨文件相对链接指向源仓库。
- JchTools：只读 `docs/requirements/README.md`、功能需求与实际注册表。
- OpenSpec：来源于离线中文文档副本，页面本身标注为旧版；不修改原文结论，只做站内链接、标题锚点、示例路径与 HTML 转义的必要修正，不与上游最新版本比对。
- JCH：只读 `skills/jch-*/SKILL.md` 与 `skills/dft-*/SKILL.md`；技能说明仅作为内容来源，不执行技能。清单支持通过显式传入技能源目录核对名称是否完整。
- 不修改、安装、测试或部署各源项目；网站验证不代表产品验收。
- 不发布企业内部域名、IP、共享盘地址、真实凭据、个人绝对路径或芯片项目资料。必须由管理员提供的地址和配置不伪造。
- 使用中文短句，命令与当前来源一致。可链接公开仓库了解细节，不复制全部原始需求，也不公开维护需求编号追溯矩阵。

## 验证与发布

依赖版本固定，提交锁文件。校验全部站内链接、标题锚点、页面清单、孤立页面、技能清单与公开内容边界；VitePress 生产构建不得忽略死链。构建产物检查保留资源、锚点与可选 HTTP 字节一致性验证。

集中运行格式检查、文档检查与真实生产构建；真实浏览器检查新增功能页、桌面与窄屏导航、中文搜索及命令显示；未变页面复用已有验证。

只提交网站仓库并推送 main，由现有 GitHub Pages Actions 发布；确认该次部署成功及线上页面可用后交付。未执行的源产品验证不得冒报通过。

# 研发工具简明指南站需求

## 目标与范围

网站发布于 https://jchanghong023.github.io/ ，仓库为 jchanghong023/jchanghong023.github.io。面向同事快速使用工具，不是作品集、需求镜像或研发验收资料库。

**读者是使用工具的同事，不是开发者或 Agent。** 只写“有什么用、按哪里、输入什么、完成后做什么”，用日常中文和短步骤；不要求读者理解内部实现、配置结构或工具协议。必要风险用一两句话讲清，技术细节留源仓库。这是后续所有网页的默认写作标准。

使用 VitePress 默认主题，保留中文导航、搜索、明暗主题、代码复制与移动端目录，不另造主题，不添加统计追踪或外部字体。

## 内容与页面

首页保留四个项目入口；OMP 提供快速指南、自有功能、黄区 CodeAgent，以及 Team、Wiki、Repo 三个独立操作说明，其余项目各维护一个内容页：

| 页面             | 内容边界                                                                                                                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/omp/`          | OMP 中文快速指南：启动、第一次对话及少量常用操作，不展开架构、需求编号或验收矩阵                                                                                                                          |
| `/omp/features`  | 保留无人值守 Goal、多模式显示、红区 shm 与其他 Fork 改动优化；Team、Wiki、Repo 的介绍正文迁到各自独立页，这里仅保留入口链接，不重复维护                                                                   |
| `/omp/codeagent` | Windows 黄区 CodeAgent 使用：先下载 JchTools、完成公司 CodeAgent 登录，打开凭据维护页，再在非 offline 的 OMP 中选择内置模型；说明同一 Windows 用户、Token 安全、后台生命周期和排错，不与 ACP 模型服务混淆 |
| `/omp/team`      | Team 方案讨论：直接发起、查看结果、确认方案与另行实施；必须用五个清晰步骤说明独立调查、对齐理解、交叉检查、修改复查、汇总推荐各做什么，不能因精简而变成黑盒；不展开配置结构、阶段协议或内部算法           |
| `/omp/wiki`      | Wiki 知识库：准备 Markdown、从面板导入、直接提问、资料变化后重新导入；不展开数据库、工具参数、游标、排名或检索实现                                                                                        |
| `/omp/repo`      | Repo 查代码：确认项目并建库、直接描述任务、外部修改后更新、必要时重建；不解释 schema、覆盖字段、解析器或增量维护机制                                                                                      |
| `/ompcode/`      | forkZcode（产品名 OmpCode）最简单的内网启动说明：取得匹配安装包、启动命令、打开项目；不展开功能大全                                                                                                       |
| `/jchtools/`     | JchTools 最基本的功能清单，每项一句话；必要的删除风险简短说明                                                                                                                                             |
| `/jch/`          | 列出全部 `jch-*`、`dft-*` 技能的功能与使用场景；三级测试技能另用简短操作说明介绍三个级别、有效通过结果的增量复用、高风险先测和任一错误立即停止整轮，不复制内部编排细节                                    |

删除原来的冗长专题页、首次使用汇总、来源覆盖页、公开边界页及 coverage.json 追溯机制；不保留可被导航、搜索检索到的旧长篇副本。导航与侧栏使用 `scripts/site-data.mjs` 的唯一页面清单。

## 来源与公开边界

- OMP：快速指南只读 `oh-my-pi/docs-zh-CN/quick-start-intranet.md`；自有功能介绍读取 `docs-zh-CN/requirements/fork.md` 及 Goal、Team、Repo、offline-shm 等相关需求。区分 Fork 新增、对上游能力的增强与适用环境，不将通用上游功能冒称自研。
- forkZcode：只读 OmpCode 的启动器与 `docs/requirements/centos7-release.md` 等相关说明；下载来源为 `jchanghong023/OmpCode`，不是上游 ZCode。
- JchTools：只读 `docs/requirements/README.md`、功能需求与实际注册表。
- 黄区 CodeAgent：结合 OMP Fork 的 CodeAgent 内置模型契约与 JchTools 的 `CODEAGENT.md`、README 和实际页面入口；不发布服务内部地址，不要求手工复制 Token 或自建 provider，不实际读取用户凭据或调用公司模型。
- JCH：只读 `skills/jch-*/SKILL.md` 与 `skills/dft-*/SKILL.md`；技能说明仅作为内容来源，不执行技能。清单支持通过显式传入技能源目录核对名称是否完整。
- 不修改、安装、测试或部署四个源项目；网站验证不代表产品验收。
- 不发布企业内部域名、IP、共享盘地址、真实凭据、个人绝对路径或芯片项目资料。必须由管理员提供的地址和配置不伪造。
- 使用中文短句，命令与当前来源一致。可链接公开仓库了解细节，不复制全部原始需求，也不公开维护需求编号追溯矩阵。
- Team、Wiki、Repo 作为企业核心功能各自成页，但“核心”不等于长篇技术手册；以首次使用和日常操作为主，不堆可选入口、重复示例、边缘规则或验收声明。其他 Fork 改动优化仍留原页面。
- 性能介绍说明具体优化机制、适用范围及限制，不声称所有场景全面提速，不从本地局部基准推导公司实网、NFS、模型推理速度或普遍倍数提升。无人值守须说明授权与阻塞边界，shm 须说明备份及数据丢失风险。

## 验证与发布

依赖版本固定，提交锁文件。校验全部站内链接、标题锚点、页面清单、孤立页面、技能清单与公开内容边界；VitePress 生产构建不得忽略死链。构建产物检查保留资源、锚点与可选 HTTP 字节一致性验证。

集中运行格式检查、文档检查与真实生产构建；真实浏览器检查新增功能页、桌面与窄屏导航、中文搜索及命令显示；未变页面复用已有验证。

只提交网站仓库并推送 main，由现有 GitHub Pages Actions 发布；确认该次部署成功及线上页面可用后交付。未执行的源产品验证不得冒报通过。
